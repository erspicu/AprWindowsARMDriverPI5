# RP1 I2S 音訊驅動移植 — Phase 1 紀錄與規則

> 日期：2026-06-21 03:31
> 主題：把 Raspberry Pi 5（RP1 南橋）的 **Synopsys DesignWare I2S** Linux 驅動，移植成 **Windows 11 on ARM (ARM64)** 驅動，並成功 build。
> 狀態：**Phase 1 完成（可編譯出 ARM64 `rp1i2s.sys`）**。

---

## 1. 成果

| 項目 | 路徑 |
|------|------|
| Windows 原始碼 | `windows_sources/audio/rp1-i2s/` |
| 建置產出（.sys/.inf） | `windows_driver/audio/rp1i2s.sys`、`rp1i2s.inf` |
| 建置腳本 | `windows_sources/audio/rp1-i2s/build.ps1` |

驗證：`dumpbin /headers rp1i2s.sys` → `AA64 machine (ARM64)`、`subsystem (Native)`、entry `GsDriverEntry`，imports `ntoskrnl.exe`（`IoCreateDevice`、`MmMapIoSpaceEx`）。

## 2. 移植來源對應（Linux → Windows）

| Linux 來源 | Windows 檔 | 內容 |
|-----------|-----------|------|
| `sources/sound/soc/dwc/local.h` | `rp1_i2s_hw.h` | 暫存器圖、bit 欄位、COMP 參數巨集（**直接沿用**） |
| `sources/sound/soc/dwc/dwc-i2s.c` | `rp1_i2s_hw.c` | `dw_i2s_config`/`i2s_start`/`i2s_stop`/`hw_params` 邏輯（**忠實移植**） |
| `readl()` / `writel()` | `READ_REGISTER_ULONG` / `WRITE_REGISTER_ULONG` | MMIO 存取（ARM64 device-memory ordering） |
| `platform_driver` + `probe()` | `driver.c`（WDM DriverEntry/AddDevice） | OS 介接層（**重寫**） |
| `devm_platform_get_and_ioremap_resource` | `pnp.c`（IRP_MN_START_DEVICE → `MmMapIoSpaceEx`） | 資源解析 + MMIO 映射（**重寫**） |

**原則**：硬體邏輯（暫存器/序列）沿用；OS 介接層（PnP、記憶體、電源）重寫。

## 3. 為何選 WDM（而非 KMDF）

- 終局是音訊 → Windows 音訊用 **PortCls/WaveRT**，而 **PortCls 本身就是 WDM 模型**。WDM 是正確的基礎，KMDF 反而是繞路。
- 手動連結時 WDM **相依最少**（只需 `BufferOverflowFastFailK.lib ntoskrnl.lib hal.lib`，entry `GsDriverEntry`）。

## 4. 建置工具鏈（重要規則）

- 本機是 **x64**，**交叉編譯**到 ARM64。
- 已安裝：**WDK 10.0.26100**（winget `Microsoft.WindowsWDK.10.0.26100`）+ VS2022「**MSVC v143 ARM64 build tools**」。
- **winget 版 WDK 不含 Visual Studio 的 MSBuild Driver 整合**（無 `WDK.vsix`、無 `WindowsKernelModeDriver10.0` toolset）→ 因此**不用 `.vcxproj`**，改用 `build.ps1` 直接呼叫 `cl.exe`/`link.exe`。

### 可用的編譯/連結配方（已驗證 ARM64）
- **include 順序（關鍵）**：`km\crt` → `km` → `shared`。
  - ⚠️ **不要**加 VC 的 user-mode include（`VC\Tools\MSVC\<ver>\include`），否則會拉到 `crtdefs.h`→`corecrt.h` 而失敗。`km\crt` 已自帶 `intrin.h`/`arm64_neon.h`/`stddef.h` 等完整 kernel CRT。
- **cl**：`/c /W4 /O2 /Gy /Zi /kernel /GS /D_WIN64 /DNDEBUG /D_ARM64_ /DARM64`
  - ⚠️ **不要**自己 `/D_KERNEL_MODE`（保留巨集，`/kernel` 已定義，會出 C4117 警告）。
- **link**：`/DRIVER /SUBSYSTEM:NATIVE,10.0 /MACHINE:ARM64 /NODEFAULTLIB /INTEGRITYCHECK /ENTRY:GsDriverEntry`
  - libpath：`Lib\10.0.26100.0\km\arm64`；libs：`BufferOverflowFastFailK.lib ntoskrnl.lib hal.lib`。

### 安裝 ARM64 元件的教訓（vs_installer）
- `vs_installer.exe modify` **不支援 `--wait`**（會印 usage 並 exit 87）。
- 用 `Start-Process -ArgumentList`（**陣列**）傳含空白路徑時，**不會自動加引號** → `C:\Program Files\...` 被截成 `C:\Program`，導致 exit 1「找不到已安裝產品」。
- **正解**：把整串參數當**單一字串**傳，路徑用引號包好：
  `Start-Process vs_installer.exe -ArgumentList 'modify --installPath "C:\Program Files\...\Community" --add Microsoft.VisualStudio.Component.VC.Tools.ARM64 --quiet --norestart' -Wait`

## 5. 尚未完成（Phase 2 待辦）

1. **PortCls/WaveRT 音訊端點**：目前只是 WDM 骨架 + HAL，還不是 Windows 認得的「音效裝置」。需實作 adapter + WaveRT miniport + topology miniport。
2. **DMA**：I2S FIFO ↔ 記憶體的資料搬運（RP1 用 DesignWare AXI-DMA），目前只開了 DMA handshake bit，未接 DMA 引擎。
3. **Codec / 時脈**：I2S 只是 CPU DAI，需搭配外接 DAC/codec 與 bit/LR clock 設定（master 模式需設 CCR + 時脈）。
4. **RP1 PCIe 列舉**：實機上 I2S 在 RP1→PCIe 底下，Windows 要先打通 PCIe + RP1 multi-function bus，並由 **ACPI** 提供 I2S 的 MMIO 資源（目前 INF 用 placeholder `ACPI\RPI5I2S0`）。
5. **簽章與載入**：ARM64 強制簽章。`build.ps1 -Sign` 會做 inf2cat + 自簽測試憑證 + signtool；載入需開測試簽章模式 / 關 HVCI。

## 6. 目錄與通用規則（沿用於後續移植）

- 原始碼：`windows_sources/<類別>/<專案>/`（類別如 `audio`、`net`、`usb`、`gpio`、`i2c`、`spi`、`serial`、`storage`、`display`；`_common/` 放共用程式碼）。
- 產出：`windows_driver/<類別>/`。
- 暫存/下載：`temp/`。
- 筆記：`MD/Note/年月日-時間-主題.md`。
- 遇技術/規格問題可用 `tools/knowledgebase/gemini_query.py`（金鑰在 `C:\key\config.json`）諮詢 Gemini；本次即用它確認了 WDK 建置方式。

## 7. 如何重建

```powershell
pwsh -File windows_sources\audio\rp1-i2s\build.ps1            # ARM64（預設）
pwsh -File windows_sources\audio\rp1-i2s\build.ps1 -Arch x64  # x64 sanity build
pwsh -File windows_sources\audio\rp1-i2s\build.ps1 -Sign      # 另做 inf2cat + 自簽
```
