# A8：BCM2712 I2C（BSC，SpbCx）

> 和 [RP1 的 DesignWare I2C（B9）](B09-rp1-designware-i2c.md) **完全不同的 IP**——BCM 自家的 BSC。
> 好教材：「同樣是 I2C，但晶片不同就是另一套暫存器 + 另一個時脈」。

## 1. 與 DesignWare I2C 的差異

| | RP1 DesignWare（B9） | BCM2712 BSC（本章） |
|---|---|---|
| 暫存器 | `DW_IC_CON/TAR/DATA_CMD…` | `BCM_I2C_C/S/DLEN/A/FIFO/DIV` |
| 速度設定 | SCL HCNT/LCNT | 單一 **DIV**（divider） |
| 輸入時脈 | clk_sys 200 MHz | **108 MHz**（`clk-108M`） |
| 傳輸 | FIFO + DATA_CMD | C 暫存器設 START/READ + FIFO |

> 教學點：**「I2C」是協定，不是 IP**。移植時要先認出「這是哪家的 I2C 控制器」。

## 2. 經典案例：DIV 用錯時脈 → 速度錯（A 類）

BSC 的速度：`SCL = core_clk / DIV`。本專案原本預設 `DIV=0x5dc(1500)` 註解寫「~100kHz」，
其實是**假設 core=150MHz** 算的。但 Pi5 實測 BCM BSC core clock = **108 MHz**（DT `clk-108M`）：
```
舊：108MHz / 1500 = 72 kHz   ← 不是 100kHz！（假設錯時脈）
正確 100kHz：DIV = 108e6 / 100000 = 1080 = 0x438
```
```c
UINT16 BcmI2cHwDivForHz(UINT32 SclHz) {           // core = 108 MHz（Pi5 實測）
    if (SclHz == 0) return 0x0438;                 // 1080 = 100kHz
    UINT32 div = (108000000u + SclHz - 1) / SclHz; // ceil
    return (UINT16)div;
}
```
> 怎麼確認 108MHz？`clk_summary` 看到 `108MHz-clock` + DT 頂層有 `clk-108M`；i2c 的 `clock-frequency=0x17cdc(97500)`
> 是 rpi 把 100kHz 設成 97500 的慣例值，與 108MHz 自洽。三方對上才敢改。

## 3. 傳輸

```c
// C 暫存器：設 START + READ/WRITE + DLEN，FIFO 收送
WR32(Base, BCM_I2C_DLEN, len);
WR32(Base, BCM_I2C_C, BCM_I2C_C_I2CEN | BCM_I2C_C_ST | (read ? BCM_I2C_C_READ : 0));
/* 輪詢 S 暫存器的 DONE / 處理 ERR/CLKT(clock stretch timeout) */
```
