## Response

這是一個極具挑戰性但非常硬核的專案！針對 BCM2712 (Raspberry Pi 5) 實作 Windows ARM64 的 KMDOD (Kernel Mode Display Only Driver)，**「務實」是唯一的指導原則**。

BCM2712 的顯示管線（尤其是時脈樹與電源域）極度複雜，如果要在 Phase 1 就在 Windows 裡用純 MMIO (Direct Register Access) 幹出完整的 HDMI Modeset，會陷入無盡的黑畫面地獄。

以下是針對你的 6 個問題，給出的可落地、工程化的高勝率執行策略：

---

### 1. KMDOD 必實作的 DDI 與 Stub 策略

為了讓 dxgkrnl (DirectX Graphics Kernel) 接受你的驅動並掛載 WARP 軟體渲染，你必須滿足最小狀態機。

**核心必做 (The Must-Haves)：**
*   `DxgkDdiStartDevice`：映射 BCM2712 的 MMIO (HVS, HDMI 等)，初始化基礎資料結構。
*   `DxgkDdiQueryChildRelations`：回報一個假的或固定的連接狀態（例如：回報 1 個 Video Output Target，狀態為 Connected）。
*   `DxgkDdiQueryDeviceDescriptor`：提供 EDID 資訊給系統。
*   **VidPn 協商三劍客**：`DdiIsSupportedVidPn`, `DdiRecommendFunctionalVidPn`, `DdiEnumVidPnCofuncModality`。一開始**不要動態計算**，全部 Hardcode 只支援一個解析度（如 1920x1080 @ 60Hz，格式 `D3DDDIFMT_X8R8G8B8`）。
*   `DxgkDdiCommitVidPn`：硬體 Modeset 的進入點。
*   `DxgkDdiSetVidPnSourceAddress`：**最重要的一步 (Flip)**。WARP 畫好一張 Framebuffer (Primary Surface) 後，會叫你把實體位址塞給硬體掃描。
*   `DxgkDdiInterruptRoutine` / `DxgkDdiDpcRoutine`：處理並回報 VSync 中斷。

**可先 Stub (回報 STATUS_NOT_SUPPORTED 或 STATUS_SUCCESS)：**
*   `DxgkDdiSetPointerShape` / `DxgkDdiSetPointerPosition`：硬體游標。回報不支援，Windows 會自動 fallback 到 WARP 畫軟體游標。
*   `DxgkDdiSetPowerState`：電源管理，先回報成功即可。
*   `DxgkDdiSystemDisplayEnable` / `Write`：Bugcheck (藍白畫面) 顯示。先跳過，用 WinDbg 看 dump 即可。
*   I2C 相關 DDIs：不需要實作標準 I2C DDI，直接在內部讀 EDID。

---

### 2. BCM2712 顯示管線 Modeset (HVS + MOP + PV + HDMI)

這是最硬的部分。Pi 5 的架構與 Pi 4 (VC6) 相似但加入了 **MOP (Main Output Pipeline)** 與 **MOPLET** 來處理 4K60 的頻寬問題。

如果你要純寫 MMIO 來 Modeset，流程如下：

*   **HVS (Hardware Video Scaler)**：
    *   **概念**：HVS 透過讀取 SRAM 裡的 **Display List (dlist)** 來合成畫面。
    *   **動作**：你需要組建一個 dlist 陣列（包含 Control Word 0, 1, 2...），定義解析度、Pixel Format (XRGB8888)、Pitch，以及 Framebuffer 的**實體位址**。然後將這個 dlist 的起始指標寫入 HVS 的 `SCALER_DISPLISTx` 暫存器。
    *   *Linux 參考*：`drivers/gpu/drm/vc4/vc4_hvs.c` (`vc4_hvs_update_dlist`)。
*   **PixelValve (PV)**：
    *   **概念**：產生 HSync, VSync, Active 等時序。
    *   **動作**：設定 H_ACTIVE, H_BLANK, V_ACTIVE, V_BLANK 等暫存器。**最困難的是時脈設定**，PV 需要對應的 Pixel Clock，這通常需要設定 CPRMAN (Clock Manager)。
    *   *Linux 參考*：`drivers/gpu/drm/vc4/vc4_crtc.c`。
*   **HDMI / PHY**：
    *   **動作**：開啟 TMDS 輸出，設定 HDMI Scrambler (若時脈 > 340MHz)，發送 AVI InfoFrame。
    *   *Linux 參考*：`drivers/gpu/drm/vc4/vc4_hdmi.c` / `vc4_hdmi_phy.c`。
*   *(需查 Linux vc4)* **MOP/MOPLET**：在 Pi 5，HVS 的輸出可能需要先 route 到 MOP 才能進 PV/HDMI，這部分的暫存器配置是全新引入的。

---

### 5. 韌體互動 vs. 純 MMIO (Phase 1 關鍵戰略)

**強烈建議 Phase 1 策略：Hybrid 模式 (Mailbox 做 Modeset，MMIO 做 Flip)**。

在 Windows 尚未有完整的 BCM2712 Clock Driver 和 Power Domain Driver 之前，直接敲 PV 和 HDMI 暫存器極容易導致系統當機或黑畫面。

**務實做法：**
1.  **交給韌體 (VideoCore FW)**：Pi 的開機程式 (`start.elf` / EEPROM) 已經把 HDMI 點亮了（有樹莓派 Logo 或 Windows 開機轉圈圈）。
2.  `DxgkDdiCommitVidPn`：**不要去動 PV 和 HDMI 暫存器**。透過 **Mailbox 介面** (Property Tags) 告訴韌體你要的解析度。
    *   使用 Mailbox Tag `0x00048003` (Set physical display width/height)
    *   使用 Mailbox Tag `0x00040001` (Allocate buffer) -> 韌體會還給你一個它配好的 Framebuffer 實體位址。
3.  `DxgkDdiSetVidPnSourceAddress` (Flip)：這裡開始用 MMIO。你把 OS 給你的新 Framebuffer 實體位址，動態更新到 HVS 的 Display List 裡。這樣就能實現高效的換頁，而不依賴緩慢的 Mailbox。

---

### 3. Framebuffer 配置與 Scanout

*   **Framebuffer 從哪來？**
    *   KMDOD 的 Framebuffer 是 dxgkrnl 從 System Memory 配給你的。
    *   **痛點**：HVS 的 DMA 只能吃**連續的實體記憶體 (Contiguous Physical Memory)**。但 OS 給的 surface 通常是分散的 (Paged)。
    *   **解法 (Phase 1)**：在 `DxgkDdiStartDevice` 時，自己用 `MmAllocateContiguousMemorySpecifyCacheNode` 預先分配 2~3 張 1080p 大小的連續記憶體當作 Front/Back buffers。
    *   當 OS 呼叫 `DxgkDdiSetVidPnSourceAddress` 給你一個邏輯 surface 時，你用 CPU (memcpy) 把 OS 的 surface 複製到你的連續記憶體，然後將連續記憶體的實體位址寫給 HVS。*(註：這對 CPU 負擔大，但對 DOD 點亮階段最穩。後續 Phase 2 再實作 WDDM 的標準 VRAM 管理 / GART)*。
*   **VSync 中斷哪裡來？**
    *   BCM2712 的顯示中斷會接到 ARM GICv2/v3。
    *   中斷源通常在 PixelValve 的 VBlank 暫存器。
    *   *(需查實機)* 在 ACPI / DSDT 表中找到顯示控制器的 IRQ 號碼。在 Windows 驅動註冊 `DxgkDdiInterruptRoutine`。
    *   中斷發生時：
        1. 讀取 PV 狀態，清除 VSync 待處理旗標 (Clear Interrupt)。
        2. `KeInsertQueueDpc` 排程 DPC。
        3. 在 DPC 裡呼叫 `DxgkCbNotifyInterrupt` 告知系統 `DXGK_INTERRUPT_CRTC_VSYNC`。

---

### 4. EDID / 解析度

**不要在 Phase 1 寫 DDC/I2C 驅動！**

1.  **Fallback 策略**：在程式碼裡 Hardcode 一個標準的 1080p60 EDID Byte Array (共 128 或 256 bytes)。
2.  當 `DxgkDdiQueryDeviceDescriptor` 被呼叫時，直接把這個 Hardcode EDID copy 給系統。
3.  系統解析後，`DxgkDdiIsSupportedVidPn` 就會收到 1920x1080 的要求。
4.  如果你非得動態讀取：使用 **Mailbox Tag `0x00030020` (Get EDID block)**。這是最安全的方法，讓 VideoCore 韌體幫你走 I2C 讀取 EDID。

---

### 6. 第一個 DOD 里程碑與驗收點

請按照以下順序進行，每一步都是一個里程碑，切勿越級打怪：

*   **Milestone 1: 欺騙 OS (The Fake Display)**
    *   **實作**：註冊基本 DDIs，回報 Hardcode EDID，`CommitVidPn` 直接 return Success（不碰任何硬體）。
    *   **驗收**：用遠端桌面 (RDP) 或 WinDbg 連入 Pi 5。在「顯示設定」裡看到系統抓到一個「一般 PnP 顯示器」，解析度為 1080p。
*   **Milestone 2: 軟體 VSync 與 WARP 啟動**
    *   **實作**：既然沒有硬體 VSync，寫一個 Windows Kernel Timer (`KeSetTimerEx`)，每 16.6ms (60Hz) 觸發一次，裡面呼叫 `DxgkCbNotifyInterrupt` 報 VSync。
    *   **驗收**：系統不會卡頓，WARP 開始將算好的桌面畫面丟給 `DxgkDdiSetVidPnSourceAddress`。
*   **Milestone 3: EFI FB 劫持 (First Pixel!)**
    *   **實作**：Windows 開機時會有一個由 Bootloader 留下的 UEFI GOP Framebuffer（畫面停在 Windows 轉圈圈）。在 `SetVidPnSourceAddress` 中，直接用 `memcpy` 將 WARP 給的 surface 複製到這個 UEFI GOP 的實體記憶體位址。
    *   **驗收**：螢幕上的轉圈圈消失，出現 Windows 桌面！此時滑鼠會動，但因為是軟體 memcpy，更新率極低（可能 < 10 FPS）。
*   **Milestone 4: HVS Hardware Flip (DOD 最終型態)**
    *   **實作**：停止 memcpy 到 EFI FB。實作預先分配 Contiguous Memory。在 `SetVidPnSourceAddress` 中，將新的實體位址寫入 BCM2712 HVS 的 Display List 並觸發更新。
    *   **驗收**：畫面流暢，CPU 使用率下降。

**總結給你的行動清單：**
1. 打開 `rp1vc4dod.sys`，把 DDIs 補齊到能過 Milestone 1。
2. 查閱 Pi 的 Mailbox 文件，準備用 Mailbox 讀 EDID。
3. 用 WinDbg 攔截 `DxgkDdiSetVidPnSourceAddress`，確認 OS 已經在給 Framebuffer。
4. 暫時不要看 Linux 的 `vc4_crtc.c` 和 `vc4_hdmi.c` (太過龐雜)，專注看 `vc4_hvs.c` 裡關於 `dlist` 組合與寫入的部分。
