## Response

這是一份針對 Raspberry Pi 5 (BCM2712) 在 Windows on ARM64 (WoA) 環境下，開發 WDDM DOD (Display Only Driver) 處理**多輸出與非 HDMI 顯示介面**的務實技術分析。

---

### 1. Pi5 顯示輸出全貌與 BCM2712 架構

**[事實]** Pi5 的 BCM2712 顯示管線架構與舊版 (BCM2835/2711) 有顯著改變。Linux `vc4` 驅動程式已經為此做了大幅重構。舊版的 HVS (Hardware Video Scaler) 概念在 BCM2712 中演進為 **MOP (Main Output Pipeline)** 與 **MOPLET (較小的 Pipeline)**。

*   **HDMI0 / HDMI1**：
    *   直接由 BCM2712 的 MOP / MOPLET 驅動。
    *   各自擁有獨立的 PixelValve (在 BCM2712 中對應新的 Timing Controller 概念) 與 PHY。
    *   **獨立性**：兩者可以完全獨立 Modeset，但共用系統記憶體頻寬。
*   **MIPI-DSI (雙 4-lane 介面)**：
    *   Pi5 板載兩個 MIPI 收發器，皆可設定為 DSI (Display) 或 CSI (Camera)。
    *   它們同樣掛載在 BCM2712 的顯示管線上，通常由另一個獨立的 CRTC (Cathode Ray Tube Controller，Linux DRM 術語，代表一個掃描輸出實例) 餵資料。
*   **VEC (Composite / 類比輸出)**：
    *   Pi5 主板上保留了 VEC 輸出的接點（需自行焊接或轉接）。
    *   由 BCM2712 內部的 VEC (Video Encoder) IP 區塊處理，通常綁定到一個特定的 Pipeline。
*   **DPI (並行 RGB)**：
    *   **[事實/重要變更]** 在 Pi4 及以前，DPI 透過 SoC 的 GPIO Alternate Functions 輸出。但在 Pi5，所有的 40-pin GPIO 都移到了 **RP1 南橋**晶片上，透過 PCIe 連接到 BCM2712。
    *   **[推測/極高機率]** 由於顯示管線的龐大頻寬需求，BCM2712 **不可能**將並行 RGB 像素資料透過 PCIe 打到 RP1 再從 GPIO 輸出。因此，Pi5 原生 GPIO **不再支援傳統 DPI 輸出**。若在 Pi5 要用 DPI，通常是外接 MIPI-DSI to DPI 的橋接晶片（Bridge IC）。

### 2. 在 WDDM DOD 怎麼表達多輸出 (Multi-head / VidPN)

在 Windows WDDM 架構中，顯示拓撲是透過 **VidPN (Video Present Network)** 來表達。

#### (1) 如何 Enumerate 多個 Video Output
*   你的 DOD 必須實作 `DxgkDdiQueryChildRelations` 介面。
*   當 Windows 呼叫這個函數時，你要回傳一個陣列，描述所有實體連接埠 (HDMI0, HDMI1, DSI, VEC)。每一個連接埠是一個 **Child Device**，擁有唯一的 `ChildUid` (例如 HDMI0=1, HDMI1=2, DSI=3)。
*   Windows 的 DXGK 會呼叫 `DxgkDdiIsSupportedVidPn` 與 `DxgkDdiEnumVidPnCofuncModality`，你的驅動要在這裡定義「哪些 Source (顯示管線/CRTC) 可以連到哪些 Target (ChildUid)」。
*   對於 HDMI×2 同時輸出，你會在 VidPN 拓撲中建立兩條 Path：`Source 0 -> Target 1 (HDMI0)` 和 `Source 1 -> Target 2 (HDMI1)`。Windows 的 DWM 會自動處理延伸桌面或同步顯示。

#### (2) 每個 Output 的差異與處理方式
*   **HDMI**：最標準。需要透過 I2C (DDC) 讀取 EDID，解析解析度後設定 TMDS/FRL 時脈，並送出 InfoFrame (AVI 封包告訴螢幕色彩格式)。
*   **DSI**：**無 EDID**。
    *   通常面板會有固定的 Timing (Resolution, Porch, VSync/HSync)。
    *   **[關鍵]** DSI 需要 **MIPI DCS (Display Command Set)** 初始化。你必須在 DOD 裡面寫一個 DSI Host Controller 的小驅動，在螢幕點亮前，透過 DSI Command 模式打一串 Hex 陣列（Init sequence，例如 Wake up, Set Pixel Format, Display On）給面板，然後再切換到 Video Mode 開始送像素。
*   **VEC**：**最死板**。只有固定的 PAL (576i) 或 NTSC (480i) Timing。完全靠寫入特定的類比暫存器來啟動，沒有 EDID 也不用 I2C 通訊。

#### (3) DSI 面板需要額外的 Panel Driver 嗎？
在標準的 WoA 商業裝置 (如 Qualcomm 筆電) 中，面板通常寫在 ACPI 中，並有一個獨立的 Panel Driver (UMDF/KMDF)。但在我們這種 **Hack/Porting 專案的 DOD 中，最務實的作法是把面板初始化序列 (Init Sequence) 直接 Hardcode 在 DOD 的 Modeset 流程裡**。背光 (Backlight) 通常是獨立的 PWM (可能在 RP1 上) 或 I2C 指令，也可寫死或另做小工具控制。

### 3. 務實優先序 (Pragmatic Priority)

對玩家或一般使用者而言，優先序絕對是：

1.  **HDMI0 (Primary)**：涵蓋 95% 的基本需求，沒有這個系統等同無法使用。
2.  **HDMI1 (Secondary)**：**強烈建議作為第二目標**。因為 HDMI0 寫好後，HDMI1 的底層硬體 IP 幾乎一樣（只是 Base Address 和 IRQ 不同）。實作 HDMI1 能讓 Pi5 在 Windows 上實現雙螢幕，這對「桌面替代品 (Desktop Replacement)」的展示意義極大。
3.  **MIPI-DSI (官方 7" 觸控螢幕)**：屬 Niche，但社群呼聲會很高（平板/車機改裝客喜歡）。挑戰在於要摸透 BCM2712 的 DSI Host IP 與面板的 Init Sequence。
4.  **VEC (Composite)**：極度 Niche（只有少數復古遊戲機/CRT 玩家需要）。加上 WoA 跑復古遊戲並非主流，優先序墊底。
5.  **DPI**：如前述，Pi5 幾乎淘汰此原生功能，**直接放棄**。

### 4. 工程量與參考來源 (Engineering Effort & Sources)

假設你已經完成了 HDMI0 DOD (包含 HVS/MOP 到 PixelValve 的打通)：

*   **新增 HDMI1**：
    *   **額外工程量：小 (+10~20%)**。
    *   主要是修改 WDDM 的 VidPN 邏輯，讓 DXGK 認識兩個 Target，並在硬體暫存器配置時支援傳入 Index (0 或 1)。
    *   參考：Microsoft WDK 的 `KMDOD` Sample (裡面有軟體模擬多螢幕的邏輯)。
*   **新增 MIPI-DSI**：
    *   **額外工程量：極大 (+100~150%)**。
    *   你需要實作 DSI PHY 的初始化、DSI Host Controller 的 Command Read/Write 介面、以及面板的 State Machine。
    *   參考：Linux 原始碼 `drivers/gpu/drm/vc4/vc4_dsi.c` (Host 邏輯) 以及 `drivers/gpu/drm/panel/panel-raspberrypi-touchscreen.c` (官方 7" 面板的 Init Sequence)。
*   **新增 VEC**：
    *   **額外工程量：中 (+40%)**。
    *   不用處理 EDID 和 I2C，但要看懂 Linux 裡那一堆 Magic Number 暫存器寫入。
    *   參考：Linux 原始碼 `drivers/gpu/drm/vc4/vc4_vec.c`。

### 5. 觸控：官方 DSI 螢幕的觸控怎麼接？

**[事實]** **觸控與顯示是兩條完全獨立的資料路徑 (Independent Paths)**。

官方的 7" DSI 螢幕，影像走 MIPI-DSI，但觸控層是透過 I2C 通訊 (通常是 FT5406 晶片)，並有一根 Interrupt (INT) pin。

在 Windows 上的最佳實務：
*   **不需要跟你的 DOD 綁在一起**。
*   如果 Pi5 的觸控 I2C 是接到 RP1 的 I2C Controller，而你已經移植/擁有 RP1 的 I2C 驅動：
    1. 你需要在 UEFI 的 **ACPI Table** (DSDT) 中，定義這顆 I2C 觸控晶片。
    2. 將它宣告為相容於 **Microsoft 標準 I2C HID 設備 (PNP0C50)**。
    3. 如果該晶片的韌體完全符合 HID over I2C 協定，Windows 內建的 `hidi2c.sys` 和 `mshidkmdf.sys` 會自動接管它，隨插即用變成 10 點觸控螢幕。
    4. **[不確定/需驗證]** 如果 FT5406 的韌體不完全相容標準 HID over I2C（官方 Pi 觸控屏早期版本有自定義 register map 的情況），你就必須寫一個獨立的 KMDF/UMDF Filter Driver，負責把 I2C 收到的 Raw Data 轉換成 Windows 認得的 HID Report Descriptor 丟給作業系統。但這完全是 HID 驅動的範疇，與顯示 DOD 無關。
