### (1) 最關鍵：WHD 如何接進 Windows kernel-mode (KMDF)

WHD 預期的是 RTOS 環境，我們必須在 Windows Kernel 中實作 `cy_rtos_*` 與 `cyhal_sdio_*` 抽象層。

#### (a) WHD 執行緒與阻塞機制的對應
**絕對不能用 ISR/DPC 跑 WHD 核心邏輯**。WHD 內部有 `WWD Thread`，負責處理所有 SDIO Event、Tx/Rx，這條 Thread 必須在 **`PASSIVE_LEVEL`** 運行，因為底層 SDIO IRP 傳輸是 blocking 的。
*   **Thread 實作**：使用 `PsCreateSystemThread` 創建系統執行緒。
*   **Blocking 實作**：使用 KMDF/WDM 的 `KSEMAPHORE` 或 `KEVENT` 配合 `KeWaitForSingleObject`。
*   **已知陷阱**：NetAdapterCx 的 datapath (Tx/Rx) callbacks 可能在 `DISPATCH_LEVEL` 觸發。**絕不可在 DISPATCH_LEVEL 呼叫 WHD 的 blocking API**。你必須實作一個 Ring Buffer，Tx 時 NetAdapterCx 塞入 Queue，然後 SetEvent 喚醒 WWD Thread 去做 SDIO 傳輸。

#### (b) OS 抽象層 (`cy_rtos_*`) 核心 API 對應
你必須自己寫一個 `cy_rtos_win.c`：
*   **Thread**：`cy_rtos_create_thread` -> 呼叫 `PsCreateSystemThread`。
*   **Semaphore**：
    *   `cy_rtos_init_semaphore` -> `KeInitializeSemaphore(sem, count, limit)`
    *   `cy_rtos_get_semaphore` -> `KeWaitForSingleObject(sem, Executive, KernelMode, FALSE, &timeout)` (需換算毫秒到 100ns 單位)。
    *   `cy_rtos_set_semaphore` -> `KeReleaseSemaphore(sem, 0, 1, FALSE)`
*   **Mutex**：`cy_rtos_init_mutex` -> `KeInitializeMutex`。
*   **Delay**：`cy_rtos_delay_milliseconds` -> `KeDelayExecutionThread(KernelMode, FALSE, &LargeInteger100ns)`
*   **Malloc**：`cy_rtos_malloc` -> `ExAllocatePool2(POOL_FLAG_NON_PAGED, size, 'DHWw')` (必須是 NonPagedPool，因為 SDIO DMA 及高 IRQL 會存取)。

#### (c) SDIO HAL (`cyhal_sdio_*`) 實作
你必須寫一個 `cyhal_sdio_win.c`：
*   **`cyhal_sdio_init`**：初始化階段。發送 IRP (`IRP_MN_QUERY_INTERFACE`) 向 Windows SD Host 索要 `GUID_SDBUS_INTERFACE_STANDARD` 介面指標，以取得 `SdBusSubmitRequest` 函式指標。
*   **`cyhal_sdio_send_cmd` (CMD52/CMD53)**：封裝成 `SDBUS_REQUEST_PACKET`，呼叫 `SdBusSubmitRequest` (見下方第2節)。
*   **`cyhal_sdio_bulk_transfer`**：對應 CMD53 Block Mode。
*   **`cyhal_sdio_irq_enable`**：這取決於你用 OOB 還是 In-band。如果是 In-band，不需要特別發硬體命令，而是掛載 Windows SDBUS 中斷 Callback。

#### (d) WHD 版本與參考
*   **Repo**：使用 Infineon 官方 GitHub repo `Infineon/wifi-host-driver` (推薦 release-v3.x 或 master)。
*   **Porting 參考**：**強烈建議參考 Zephyr RTOS 的實作** (`zephyr/drivers/wifi/infineon/cyw43xxx/`)。Zephyr 也是將 WHD 當作 library 引入，它的 `cybsp_wifi_os.c` 和 `cyhal_sdio_zephyr.c` 就是完美的「非原生 Infineon 平台」porting 範本，你只需把 Zephyr API 換成上述的 Windows Kernel API。

### (2) SDIO Function Driver 具體實作

#### (a) 驅動模型與掛載
*   使用 **KMDF**。
*   機制：你的驅動在 INF 檔中宣告 match SDIO ID（例如 `SD\VID_02D0&PID_A9A6`）。
*   在 `EvtDeviceAdd` 中，使用 `WdfFdoQueryForInterface` (或手動建 IRP) 取得 SD 匯流排介面：
    ```c
    SDBUS_INTERFACE_STANDARD SdBusInterface;
    // ... WdfFdoQueryForInterface(&GUID_SDBUS_INTERFACE_STANDARD, &SdBusInterface);
    ```

#### (b) CMD52 / CMD53 呼叫骨架 (Synchronous)
WHD 需要你提供暫存器讀寫能力。
```c
NTSTATUS SdioCmd52(PSDBUS_INTERFACE_STANDARD SdBus, UCHAR FuncNum, ULONG Address, UCHAR *Data, BOOLEAN IsWrite) {
    SDBUS_REQUEST_PACKET request = {0};
    request.RequestFunction = IsWrite ? SDBUS_REQUEST_TYPE_WRITE_REG : SDBUS_REQUEST_TYPE_READ_REG;
    request.Parameters.DeviceCommand.Function = FuncNum;
    request.Parameters.DeviceCommand.Address = Address;
    if (IsWrite) request.Parameters.DeviceCommand.Data = *Data;

    // SdBusSubmitRequest 需要 IRP
    PIRP Irp = IoAllocateIrp(DeviceObject->StackSize, FALSE);
    // ... 設定 IoCompletionRoutine 等待 IRP 完成
    NTSTATUS status = SdBus.SubmitRequest(SdBus.Context, &request, Irp);
    // ... 等待 Event
    if (!IsWrite) *Data = request.Parameters.DeviceCommand.Data;
    return status;
}

// CMD53 類似，RequestFunction 改用 SDBUS_REQUEST_TYPE_READ_MULTI_BLOCK
// 需填寫 request.Parameters.DeviceCommand.Length 與 Buffer
```
*   **已知陷阱**：`SdBusSubmitRequest` 是非同步的 (回傳 STATUS_PENDING)，但 WHD 預期同步返回。你必須自己 Allocate IRP，設定 Completion Routine，然後 `KeWaitForSingleObject` 阻塞當前 Thread 直到 IRP 完成。

#### (c) SDIO In-band Interrupt
*   **註冊**：在拿到 `SDBUS_INTERFACE_STANDARD` 後，呼叫 `InitializeInterface` (這是在介面結構內的一個函式指標)，並傳入你的 Callback 函式 `PSDBUS_CALLBACK_ROUTINE`。
*   **收中斷**：當 SDIO DAT1 拉低，Windows sdbus 會呼叫你的 Callback。你在 Callback 中 SetEvent 喚醒 WHD Thread 去讀取中斷狀態暫存器。
*   **Ack**：每次處理完，需發送 `SDBUS_REQUEST_TYPE_ACKNOWLEDGE_INT` 給 sdbus 重新 arm 中斷。

#### (d) SD Host 能力
*   **這裡需實機試**： 理論上 `sdbus.sys` 會在列舉時自動切換 1.8V 且設定 High-Speed (50MHz)。但 Pi5 的 Broadcom SD Host Controller 驅動在 Windows 上可能有雷。你需要透過 `SDBUS_REQUEST_TYPE_GET_PROPERTY` 讀取 `SDBUS_PROPERTY_BLOCK_SIZE` 來對齊 WHD 內部的 buffer size。

### (3) OOB GPIO 中斷 + ACPI

#### (a) ACPI ASL 宣告
OOB IRQ GPIO 應該掛在 **SDIO Function 子裝置**下，而不是 Host Controller 本身。
```asl
Device (BRC3) { // 假設掛在 SD Host 下的 WiFi 子裝置
    Name (_ADR, 1) // SDIO Function 1
    Method (_CRS, 0, NotSerialized) {
        Name (RBUF, ResourceTemplate () {
            // WL_HOST_WAKE (假設在 Pi5 的 GPIO 某個 PIN)
            GpioInt (Edge, ActiveHigh, ExclusiveAndWake, PullNone, 0, "\\_SB.GPI0") { <PIN_NUMBER> }
        })
        Return (RBUF)
    }
}
```

#### (b) 連接 OOB 中斷
在 KMDF 的 `EvtDevicePrepareHardware` 中：
1.  找到 Resource List 中的 `CmResourceTypeInterrupt`。
2.  呼叫 `WdfInterruptCreate`。
3.  在 `EvtInterruptIsr` 中，保存狀態並 Queue DPC (`WdfInterruptQueueDpcForIsr`)。
4.  在 DPC 中 SetEvent 喚醒 WWD Thread。

#### (c) 選擇：In-band 還是 OOB？
*   **MVP 階段**：**絕對先用 OOB (Polling 亦可)**。
*   **原因**：Windows `sdbus.sys` 處理 In-band 中斷的延遲極高，且在 Broadcom 晶片上容易漏中斷。WHD 支援純 Polling mode (在 WWD thread 裡一直 polling 狀態暫存器)，**強烈建議 MVP 先把 WHD 設為 Polling Mode**，確定資料打得通，再來接 OOB GPIO 中斷。不建議死磕 In-band。

### (4) NetAdapterCx 資料路徑 (802.3 進出)

這是最容易出 IRQL Bug 的地方。

#### (a) Rx (接收)：WHD -> Windows
1.  WHD Thread 從 SDIO 讀到一包資料 (WHD 吐出 Ethernet Frame)。
2.  呼叫你實作的 `whd_network_process_ethernet_data`。
3.  在這裡，你把資料放進自己寫的 Lookaside List 或 Ring Buffer，然後呼叫 `NetRxQueueNotifyMoreAdvanced` (通知 NetAdapterCx 有資料)。
4.  Windows 會在適當時間呼叫你的 `EvtPacketQueueAdvance` (RxQueue)：
    ```c
    // Rx Advance 骨架
    while(NetRingHasUnfragmentedPackets(pr)) {
        UINT32 idx = pr->NextIndex;
        NET_FRAGMENT *frag = NetRingGetFragmentAtIndex(fr, idx);
        // 從你的 Buffer 複製資料到 frag->OsReturnedBuffer
        frag->ValidLength = pkt_len;
        frag->Offset = 0;
        pr->NextIndex = NetRingIncrementIndex(pr, idx);
    }
    ```

#### (b) Tx (發送)：Windows -> WHD
1.  Windows 呼叫你的 `EvtPacketQueueAdvance` (TxQueue)。
    ```c
    // Tx Advance 骨架
    while(NetRingHasElements(pr)) {
        UINT32 idx = pr->NextIndex;
        NET_FRAGMENT *frag = NetRingGetFragmentAtIndex(fr, idx);
        // 1. 申請 WHD Buffer: whd_host_buffer_get()
        // 2. 複製 frag->OsReturnedBuffer 到 WHD Buffer
        // 3. 把指標丟給你的 WWD Worker Thread Queue
        pr->NextIndex = NetRingIncrementIndex(pr, idx);
    }
    KeSetEvent(&TxNotifyEvent, 0, FALSE); // 喚醒 WWD Thread
    ```
2.  WWD Thread 被喚醒，呼叫 `whd_network_send_ethernet_data` 將封包透過 SDIO 送出。

#### (c) 同步機制 (非常關鍵)
*   **NetAdapterCx Rx/Tx Advance**：通常在 `DISPATCH_LEVEL` (如果開啟 Polling) 或 `PASSIVE_LEVEL`。
*   **WHD Core Thread**：`PASSIVE_LEVEL`。
*   **解法**：**中間一定要隔著一層 Queue 與 Event**。Tx 時，NetAdapter 負責把 packet 複製出來放進 Queue，然後 SetEvent；WHD 負責等 Event 並發送。Rx 時，WHD 讀完放入 Queue，然後呼叫 RxNotify 讓 NetAdapterCx 來取。**不要嘗試做 Zero-copy (零拷貝)**，MVP 階段用 `RtlCopyMemory` 最穩。

### (5) 整體骨架與資料流

#### 模組分層與 API 關係圖

```text
[ Windows 網路堆疊 (TCPIP.sys) ]
           |
           v
+-------------------------------------------------------+
|  NetAdapterCx (微軟提供)                              |
+-------------------------------------------------------+
           | (EvtPacketQueueAdvance / NetRxQueueNotifyMoreAdvanced)
           |   [IRQL: <= DISPATCH_LEVEL]
           v
+-------------------------------------------------------+
|  你的 KMDF 驅動 (Pi5CywWifi.sys)                      |
|  - WDF 裝置初始化, ACPI/OOB 中斷解析                  |
|  - Rx/Tx Ring Buffers (同步層)                        |
|  - 系統執行緒創建 (PsCreateSystemThread)              |
+-------------------------------------------------------+
           | (KeWaitForSingleObject / KeSetEvent)
           |   [IRQL: PASSIVE_LEVEL 絕對邊界]
           v
+-------------------------------------------------------+
|  WHD Core (純 C Library 靜態連結進你的 sys)           |
|  - WWD Thread (無限迴圈, 處理 WiFi 狀態機)            |
|  - whd_rtos_win.c (KeInitializeSemaphore, etc.)       |
+-------------------------------------------------------+
           | (cyhal_sdio_send_cmd / cyhal_sdio_bulk_transfer)
           v
+-------------------------------------------------------+
|  WHD SDIO HAL (cyhal_sdio_win.c)                      |
|  - 建立 IRP                                           |
|  - 封裝 SDBUS_REQUEST_PACKET                          |
+-------------------------------------------------------+
           | (SdBusSubmitRequest)
           v
[ sdbus.sys (Windows 內建 SD 匯流排驅動) ]
           |
           v
[ bcm_sdhc.sys (Pi5 Broadcom SD Host 驅動) ] -> 硬體 CMD/DAT
```

#### 動手實作順序建議
1.  **Skeleton Driver**：寫一個能被掛載到 SDIO 上的 KMDF 空殼，證明 FDO 綁定成功。
2.  **SDBUS 測試**：寫 `cyhal_sdio_win.c`，在 DriverEntry 故意發送 CMD52 讀取 CYW43455 的 Backplane 暫存器。如果能讀出 Chip ID (0x4345)，這條路就通了 80%。
3.  **WHD 整合**：編譯 WHD 程式碼進來，實作 Thread 和 Semaphore，在 `PASSIVE_LEVEL` 啟動 WHD 初始化流程 (`whd_wifi_on`)，使用 **Polling Mode** 確認能跟 Firmware 溝通並載入 FW (`.bin` 檔)。
4.  **NetAdapterCx 整合**：最後才實作 Rx/Tx Queue 掛上虛擬網卡，並處理 Buffer 拷貝。
