Here is the exact, minimal specification for building an ARM64 Kernel Mode Display-Only Driver (KMDOD) using WDK 10.0.26100 via direct CLI.

### 1. DriverEntry & Initialization Data
**Important Correction**: For a Display-Only Driver, you do **not** use `DRIVER_INITIALIZATION_DATA`. You must use `KMDDOD_INITIALIZATION_DATA`. 

WDK 10.0.26100 aligns with Windows 11 24H2, which introduces **WDDM 3.2**. The correct version constant is `DXGKDDI_INTERFACE_VERSION_WDDM3_2`.

```c
#include <ntddk.h>
#include <dispmprt.h>

extern "C" DRIVER_INITIALIZE DriverEntry;

#pragma alloc_text("INIT", DriverEntry)

extern "C" NTSTATUS DriverEntry(
    _In_ PDRIVER_OBJECT DriverObject,
    _In_ PUNICODE_STRING RegistryPath)
{
    KMDDOD_INITIALIZATION_DATA dodInit = { 0 };

    // WDK 26100 / Win11 24H2 is WDDM 3.2
    dodInit.Version = DXGKDDI_INTERFACE_VERSION_WDDM3_2;

    // Fill in your implemented callbacks here (see Section 2)
    dodInit.DxgkDdiAddDevice = BasicDodAddDevice;
    dodInit.DxgkDdiStartDevice = BasicDodStartDevice;
    // ...

    // Register with the DirectX Graphics Kernel
    return DxgkInitializeDisplayOnlyDriver(DriverObject, RegistryPath, &dodInit);
}
```

### 2. DXGKDDI Callbacks (Mandatory vs. Optional)
To successfully load a minimal KMDOD (and not immediately fail `DxgkInitializeDisplayOnlyDriver`), map these exact function pointers in `KMDDOD_INITIALIZATION_DATA`.

**MANDATORY (Must be implemented and mapped):**
*   `DxgkDdiAddDevice`
*   `DxgkDdiStartDevice`
*   `DxgkDdiStopDevice`
*   `DxgkDdiRemoveDevice`
*   `DxgkDdiQueryChildRelations`
*   `DxgkDdiQueryChildStatus`
*   `DxgkDdiQueryDeviceDescriptor`
*   `DxgkDdiSetPowerState`
*   `DxgkDdiQueryAdapterInfo`
*   `DxgkDdiIsSupportedVidPn`
*   `DxgkDdiRecommendFunctionalVidPn`
*   `DxgkDdiEnumVidPnCofuncModality`
*   `DxgkDdiSetVidPnSourceVisibility`
*   `DxgkDdiCommitVidPn`
*   `DxgkDdiUpdateActiveVidPnPresentPath`
*   `DxgkDdiRecommendMonitorModes`

*   `DxgkDdiPresentDisplayOnly`

**OPTIONAL (Can be left `NULL` for a minimal bootable DOD):**

*   `DxgkDdiSystemDisplayWrite` *(Leave NULL for minimal upbring)*

### 3. Exact Headers and Link Libraries

**Headers to Include:**
You only need these two, strictly in this order:
1. `#include <ntddk.h>`
2. `#include <dispmprt.h>` *(This automatically pulls in `d3dkmddi.h`, `dxgiddi.h`, etc.)*

**Required Link Libraries:**
*   `dxgkrnl.lib` *(Contains `DxgkInitializeDisplayOnlyDriver`)*
*   `ntoskrnl.lib`
*   `hal.lib`
*   `libcntpr.lib`
*   `BufferOverflowFastFailK.lib` *(Needed for `/GS` in kernel mode)*

*(Note: `displib.lib` is only needed if you are using Microsoft's optional C++ `DispMgr` helper classes, which are not required for a custom minimal DOD).*

### 4. CL.exe and LINK.exe Flags for ARM64

Assuming environment variables like `%WDK_INC%` and `%WDK_LIB%` point to `C:\Program Files (x86)\Windows Kits\10\...\10.0.26100.0`.

**CL.exe (Compiler):**
```cmd
cl.exe /c /nologo /W4 /WX /O2 /kernel ^
    /D _ARM64_ /D ARM64 /D _KERNEL_MODE /D STD_CALL ^
    /I"%WDK_INC%\km" /I"%WDK_INC%\shared" /I"%WDK_INC%\crt" ^
    /Zc:strictStrings /GS /Zi ^
    driver.c
```
*(Note: AAPCS64 is the standard calling convention on ARM64; `STD_CALL` and `__stdcall` are simply parsed and ignored by the ARM64 compiler, but WDK headers require the defines to avoid syntax errors).*

**LINK.exe (Linker):**
```cmd
link.exe /nologo /MACHINE:ARM64 /kernel ^
    /SUBSYSTEM:NATIVE,10.0 /OSVERSION:10.0 ^
    /DRIVER:WDM /ENTRY:DriverEntry ^
    /NODEFAULTLIB /OPT:REF /OPT:ICF /INCREMENTAL:NO ^
    /LIBPATH:"%WDK_LIB%\km\arm64" ^
    dxgkrnl.lib ntoskrnl.lib hal.lib libcntpr.lib BufferOverflowFastFailK.lib ^
    /OUT:mydod.sys ^
    driver.obj
```
