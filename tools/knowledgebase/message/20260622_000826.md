### 1. ACPI DSDT 描述 (ASL 骨架)

在 Raspberry Pi 5 (RP1) 的環境下，藍牙通常接在 RP1 的某個 PL011 UART（例如 `URT0`）和 GPIO 控制器上。為了讓 Windows 的 SerCx2 (UART) 和 GPIO 框架能把資源派發給你的 BT Driver，必須使用 `UartSerialBusV2`、`GpioIo` 和 `GpioInt`。

**_HID 的選擇**：建議使用標準的 Broadcom 藍牙 ID（如 `BCM2E1A` 或 `BCM4345`），或者自訂如 `RP1BTHX0`，只要與 INF 中的 `HardwareId` 匹配即可。

```asl
// 假設這個裝置放在 RP1 的 Scope 底下，或是獨立的 Scope 但 Reference 到 RP1 的設備
Device (BTH0)
{
    Name (_HID, "BCM2E1A") // 或自訂 "RP1BTHX0"
    Name (_CID, "BCM2E1A")
    Name (_UID, 0)

    Method (_CRS, 0, NotSerialized)
    {
        Name (SBUF, ResourceTemplate ()
        {
            // 1. UART 連線 (指向 RP1 的 PL011 UART)
            UartSerialBusV2 (
                115200,                      // Initial BaudRate (BCM 預設通常是 115200)
                DataBitsEight,
                StopBitsOne,
                0xFC,                        // LinesInUse: 8 data bits
                LittleEndian,
                ParityTypeNone,
                FlowControlHardware,         // BCM 需要 RTS/CTS flow control
                32, 32,                      // Rx/Tx buffer size
                "\\_SB.PCI0.RP1.URT0",       // ResourceSource: 指向提供 UART 的 Controller (請依你的 rp1.asl 修改)
                0, ResourceConsumer, , 
            )

            // 2. BT_REG_ON (GPIO 輸出，用來喚醒/Reset BT 晶片)
            GpioIo (Shared, PullDefault, 0, 0, IoRestrictionOutputOnly,
                "\\_SB.PCI0.RP1.GPIO",       // ResourceSource: 指向 RP1 GPIO Controller
                0, ResourceConsumer, , )
                { 12 }                       // 假設 BT_REG_ON 接在 RP1 GPIO 12

            // 3. BT_HOST_WAKE (GPIO 中斷，BT 喚醒 Host)
            GpioInt (Edge, ActiveHigh, Exclusive, PullDown, 0,
                "\\_SB.PCI0.RP1.GPIO", 
                0, ResourceConsumer, , )
                { 13 }                       // 假設 BT_HOST_WAKE 接在 RP1 GPIO 13
        })
        Return (SBUF)
    }
}
```

### 2. Driver 怎麼從 _CRS 拿到 UART 與 GPIO (`EvtDevicePrepareHardware`)

在 `EvtDevicePrepareHardware` 中，ACPI 的 `GpioInt` 會被轉換為 `CmResourceTypeInterrupt`，而 `UartSerialBusV2` 和 `GpioIo` 都會變成 `CmResourceTypeConnection`。

#### 解析與分辨
```c
NTSTATUS EvtDevicePrepareHardware(WDFDEVICE Device, WDFCMRESLIST ResourcesRaw, WDFCMRESLIST ResourcesTranslated)
{
    ULONG resourceCount = WdfCmResourceListGetCount(ResourcesTranslated);
    PCM_PARTIAL_RESOURCE_DESCRIPTOR res;
    
    LARGE_INTEGER uartConnectionId = {0};
    LARGE_INTEGER gpioConnectionId = {0};
    
    for (ULONG i = 0; i < resourceCount; i++) {
        res = WdfCmResourceListGetDescriptor(ResourcesTranslated, i);

        if (res->Type == CmResourceTypeConnection) {
            if (res->u.Connection.Class == CM_RESOURCE_CONNECTION_CLASS_SERIAL) {
                // 抓到 UART
                uartConnectionId.LowPart = res->u.Connection.IdLowPart;
                uartConnectionId.HighPart = res->u.Connection.IdHighPart;
            } 
            else if (res->u.Connection.Class == CM_RESOURCE_CONNECTION_CLASS_GPIO) {
                // 抓到 GPIO (BT_REG_ON)
                gpioConnectionId.LowPart = res->u.Connection.IdLowPart;
                gpioConnectionId.HighPart = res->u.Connection.IdHighPart;
            }
        }
        else if (res->Type == CmResourceTypeInterrupt) {
            // 抓到 GpioInt (BT_HOST_WAKE)
            // 直接用 WdfInterruptCreate 掛載 ISR，不用開 Connection
            // WDF_INTERRUPT_CONFIG_INIT(&interruptConfig, EvtInterruptIsr, EvtInterruptDpc);
            // interruptConfig.InterruptTranslated = res;
            // interruptConfig.InterruptRaw = WdfCmResourceListGetDescriptor(ResourcesRaw, i);
            // WdfInterruptCreate(Device, &interruptConfig, WDF_NO_OBJECT_ATTRIBUTES, &InterruptObj);
        }
    }
    
    // ... 後續開啟 UART 與 GPIO Target ...
}
```

#### 開啟 Target (UART 與 GPIO)
做法皆是：使用 `RESOURCE_HUB_CREATE_PATH_FROM_ID` 產生 Device Path，然後 `WdfIoTargetOpen`。

```c
NTSTATUS OpenIoTarget(WDFDEVICE Device, LARGE_INTEGER ConnectionId, WDFIOTARGET* Target)
{
    NTSTATUS status;
    DECLARE_UNICODE_STRING_SIZE(devicePath, RESOURCE_HUB_PATH_SIZE);
    
    // 轉成巨集定義的字串路徑 (需 include <reshub.h>)
    RESOURCE_HUB_CREATE_PATH_FROM_ID(&devicePath, ConnectionId.LowPart, ConnectionId.HighPart);

    WDF_IO_TARGET_OPEN_PARAMS openParams;
    WDF_IO_TARGET_OPEN_PARAMS_INIT_OPEN_BY_NAME(&openParams, &devicePath, GENERIC_READ | GENERIC_WRITE);
    // UART 建議獨佔，GPIO 也是
    openParams.ShareAccess = 0; 

    WdfIoTargetCreate(Device, WDF_NO_OBJECT_ATTRIBUTES, Target);
    status = WdfIoTargetOpen(*Target, &openParams);
    return status;
}
```

#### 控制 GPIO (BT_REG_ON) High/Low
你需要包含 `<gpio.h>`。使用 `IOCTL_GPIO_WRITE_PINS`。

```c
NTSTATUS SetGpioState(WDFIOTARGET GpioTarget, UCHAR State)
{
    // State: 1 for High, 0 for Low
    GPIO_CLIENT_WRITE_PINS_MASK writeMask;
    writeMask.Mask = 1; // 第一根 Pin (這裡只有1根)
    writeMask.SetParameters.PinValues = State ? 1 : 0;

    WDF_MEMORY_DESCRIPTOR inputDesc;
    WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&inputDesc, &writeMask, sizeof(writeMask));

    // 同步發送 IOCTL
    return WdfIoTargetSendIoctlSynchronously(
        GpioTarget, 
        NULL, 
        IOCTL_GPIO_WRITE_PINS, 
        &inputDesc, 
        NULL, 
        NULL, 
        NULL
    );
}
```

### 3. Init 期間同步收發 HCI Event (.hcd 載入期)

在 Driver `EvtDeviceD0Entry` 期間，`bthport` 尚未建立 Read Pump，你需要手動透過 UART 發送 HCI 指令（例如 `0x01 0x03 0x0C 0x00` -> HCI_Reset）並讀取回應（`0x04 0x0E 0x04 ...` -> Command Complete）。

**H4 Protocol 概念**：
- `0x01` : HCI Command (Tx)
- `0x04` : HCI Event (Rx)

#### 同步收發骨架 (Read Pump 前的初始化)
這必須在 `PASSIVE_LEVEL` 執行（`EvtDeviceD0Entry` 符合）。

```c
NTSTATUS SendHciCommandAndWaitForEvent(
    WDFIOTARGET UartTarget,
    PUCHAR Command, ULONG CommandLength,
    PUCHAR EventBuffer, ULONG EventBufferLength,
    PULONG BytesRead)
{
    NTSTATUS status;
    WDF_REQUEST_SEND_OPTIONS timeoutOptions;
    
    // 1. 設定 Timeout (例如 2 秒 = -20000000 100-ns intervals)
    WDF_REQUEST_SEND_OPTIONS_INIT(&timeoutOptions, WDF_REQUEST_SEND_OPTION_TIMEOUT);
    WDF_REQUEST_SEND_OPTIONS_SET_TIMEOUT(&timeoutOptions, WDF_REL_TIMEOUT_IN_SEC(2));

    // 2. 寫入 Command (同步)
    WDF_MEMORY_DESCRIPTOR txDesc;
    WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&txDesc, Command, CommandLength);
    status = WdfIoTargetSendWriteSynchronously(UartTarget, NULL, &txDesc, NULL, &timeoutOptions, NULL);
    if (!NT_SUCCESS(status)) return status;

    // 3. 讀取回應 (H4 解析迴圈)
    // 注意：UART 是 stream，必須分次讀取。先讀 1 byte 判斷 Packet Type。
    UCHAR pktType = 0;
    WDF_MEMORY_DESCRIPTOR rxDesc;
    ULONG_PTR bytesReturned;

    WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&rxDesc, &pktType, 1);
    status = WdfIoTargetSendReadSynchronously(UartTarget, NULL, &rxDesc, NULL, &timeoutOptions, &bytesReturned);
    if (!NT_SUCCESS(status) || pktType != 0x04) return STATUS_UNSUCCESSFUL; // 不是 Event

    // 讀取 Event Header (2 bytes: Event Code + Parameter Total Length)
    UCHAR evtHeader[2] = {0};
    WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&rxDesc, evtHeader, 2);
    status = WdfIoTargetSendReadSynchronously(UartTarget, NULL, &rxDesc, NULL, &timeoutOptions, &bytesReturned);
    if (!NT_SUCCESS(status)) return status;

    UCHAR eventCode = evtHeader[0];
    UCHAR paramLen = evtHeader[1];

    if (paramLen > EventBufferLength - 3) return STATUS_BUFFER_TOO_SMALL;

    // 將收到的資料裝入呼叫者的 Buffer
    EventBuffer[0] = pktType;
    EventBuffer[1] = eventCode;
    EventBuffer[2] = paramLen;

    // 讀取剩餘的 Parameters
    if (paramLen > 0) {
        WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&rxDesc, EventBuffer + 3, paramLen);
        status = WdfIoTargetSendReadSynchronously(UartTarget, NULL, &rxDesc, NULL, &timeoutOptions, &bytesReturned);
        if (!NT_SUCCESS(status)) return status;
    }

    *BytesRead = 3 + paramLen;

    // 檢查是否為 Command Complete (0x0E)
    if (eventCode == 0x0E) {
        // 解析 EventBuffer[3] = NumHCICommandPackets, EventBuffer[4..5] = Opcode 等
        return STATUS_SUCCESS;
    }

    return STATUS_MORE_PROCESSING_REQUIRED; // 收到其他 Event，可能要繼續 loop (此處簡化)
}
```

### 4. INF + Build 相關細節

#### bthx.h 的位置
- 確切位置在 WDK 中：`$(DDK_INC_PATH)\shared\bthx.h` （通常在 `C:\Program Files (x86)\Windows Kits\10\Include\<version>\shared\bthx.h`）。
- 用法：裡面定義了 `IOCTL_BTHX_READ_HCI`、`IOCTL_BTHX_WRITE_HCI` 等，你的 driver 的核心機制就是註冊一個 Queue 來處理這些來自 `bthport.sys` 的 IOCTL。

#### Build 與 Lib
- **Entry Point**: 標準 WDF `FxDriverEntry` 即可（不需要寫特製的 Entry，常規 `DriverEntry` 呼叫 `WdfDriverCreate` 即可）。
- **Libs**: 不需要特殊的 Lib。只需要標準的 `wdf.lib`, `wdm.lib`。BTHX 是一個純粹基於 Device Interface 和 IOCTL 的架構，沒有像 NDIS 或 Storport 那種需要 link 特殊 wrapper library 的限制。

#### INF 寫法骨架 (疊在 Bthport 之下)
關鍵在於 `Class` 和 `Include/Needs`，讓系統的 Bluetooth 核心驅動（`bthport.sys` 等）能認得並疊加在你之上。

```inf
[Version]
Signature="$WINDOWS NT$"
Class=Bluetooth
ClassGuid={e0cbf06c-cd8b-4647-bb8a-263b43f0f974}
Provider=%ProviderName%
DriverVer=...
CatalogFile=rp1bthx.cat

[Manufacturer]
%ManufacturerName%=Standard,NTARM64

[Standard.NTARM64]
%DeviceDesc%=Rp1Bthx_Device, ACPI\BCM2E1A  ; 對應 ASL 的 _HID

[Rp1Bthx_Device.NT]
CopyFiles=Drivers_Dir
; Include Microsoft Inbox Bluetooth definitions
Include=bth.inf
Needs=BthUsb.NT  ; 對，即使是 UART BTHX，微軟標準架構常透過 BthUsb.NT 或 BthLEnum 來設定上緣

[Rp1Bthx_Device.NT.HW]
AddReg=Rp1Bthx_Device.HW.AddReg
Include=bth.inf
Needs=BthUsb.NT.HW

[Rp1Bthx_Device.HW.AddReg]
; 這是關鍵：宣告你的 Driver 支援 BTHX Transport 介面
HKR, , "BthxTransport", 0x00010001, 1 
; 宣告你支援的 BTHX 協定 (0=USB, 1=UART/H4)
HKR, , "BthxProtocol",  0x00010001, 1 

[Rp1Bthx_Device.NT.Services]
; 將你的 Driver 設為基礎 Service，bthport 會掛在上面 (透過 bth.inf 的 Needs)
AddService=rp1bthx, 0x00000002, Rp1Bthx_Service_Inst 
Include=bth.inf
Needs=BthUsb.NT.Services

[Rp1Bthx_Service_Inst]
DisplayName    = %ServiceDesc%
ServiceType    = 1               ; SERVICE_KERNEL_DRIVER
StartType      = 3               ; SERVICE_DEMAND_START
ErrorControl   = 1               ; SERVICE_ERROR_NORMAL
ServiceBinary  = %12%\rp1bthx.sys
```
*註：這是在 Windows 架構中實作自訂 BTHX 的標準 hack。雖然你的下緣是 UART，但微軟上緣（Bthport）與 BTHX Extension 通訊的註冊點，最完整且相容的 `Needs` 區塊往往是借用 `BthUsb.NT` 的設定，因為它預設帶起完整的 BTHX stack，再透過 `BthxTransport=1` 和 `BthxProtocol=1` 來告訴 Bthport 走 BTHX 介面（而非原生 USB 介面）。*
