### A. NetAdapterCx 網卡端設定程式骨架

在 NetAdapterCx (2.0+) 的架構中，網卡初始化分為兩階段：先建立 WDF Device，再建立 NETADAPTER。

#### 1 & 2. 初始化、建立 Adapter 與 Capabilities 設定

在 `EvtDriverDeviceAdd` 中，我們需要依照嚴格的順序初始化：

```c
NTSTATUS
EvtDriverDeviceAdd(
    _In_ WDFDRIVER Driver,
    _Inout_ PWDFDEVICE_INIT DeviceInit
)
{
    NTSTATUS status;
    WDFDEVICE device;
    NETADAPTER adapter;
    PNET_DEVICE_INIT netDeviceInit = NULL;

    // 1. 分配並設定 NET_DEVICE_INIT
    netDeviceInit = NetDeviceInitAllocate(DeviceInit);
    if (netDeviceInit == NULL) {
        return STATUS_INSUFFICIENT_RESOURCES;
    }

    // 允許 NetAdapterCx 預先處理 WDFDEVICE_INIT
    status = NetDeviceInitConfig(netDeviceInit);
    if (!NT_SUCCESS(status)) {
        NetDeviceInitFree(netDeviceInit);
        return status;
    }

    // 2. 建立 WDF Device
    WDF_OBJECT_ATTRIBUTES deviceAttributes;
    WDF_OBJECT_ATTRIBUTES_INIT_CONTEXT_TYPE(&deviceAttributes, MY_DEVICE_CONTEXT);
    status = WdfDeviceCreate(&DeviceInit, &deviceAttributes, &device);
    if (!NT_SUCCESS(status)) {
        NetDeviceInitFree(netDeviceInit);
        return status;
    }
    // 成功建立 WDFDevice 後，NetDeviceInit 會被自動清理，不需要再 Free。

    // --- 準備建立 NETADAPTER ---
    NETADAPTER_INIT* adapterInit = NetAdapterInitAllocate(device);
    if (adapterInit == NULL) return STATUS_INSUFFICIENT_RESOURCES;

    // 綁定 Datapath 回呼函數 (Tx / Rx Queue 建立)
    NET_ADAPTER_DATAPATH_CALLBACKS datapathCallbacks;
    NET_ADAPTER_DATAPATH_CALLBACKS_INIT(&datapathCallbacks, EvtAdapterCreateTxQueue, EvtAdapterCreateRxQueue);
    NetAdapterInitSetDatapathCallbacks(adapterInit, &datapathCallbacks);

    // 建立 NETADAPTER
    WDF_OBJECT_ATTRIBUTES adapterAttributes;
    WDF_OBJECT_ATTRIBUTES_INIT_CONTEXT_TYPE(&adapterAttributes, MY_ADAPTER_CONTEXT);
    status = NetAdapterCreate(adapterInit, &adapterAttributes, &adapter);
    NetAdapterInitFree(adapterInit); // 必須釋放

    // --- 設定 Capabilities ---

    // A. 設定 MAC Address (這裡假設已經透過 WHD/SDIO 拿到 MAC)
    NET_ADAPTER_LINK_LAYER_ADDRESS linkAddress;
    NET_ADAPTER_LINK_LAYER_ADDRESS_INIT(&linkAddress, 6, MyMacAddressBuffer);
    NetAdapterSetPermanentLinkLayerAddress(adapter, &linkAddress);
    NetAdapterSetCurrentLinkLayerAddress(adapter, &linkAddress);

    // B. 設定 MTU (乙太網通常是 1500)
    NET_ADAPTER_LINK_LAYER_CAPABILITIES linkLayerCaps;
    NET_ADAPTER_LINK_LAYER_CAPABILITIES_INIT(&linkLayerCaps,
        1500000ull, // 1.5 Mbps (可以填 WiFi 的最大預期速率，或假裝 1Gbps: 1000000000ull)
        1500000ull);
    linkLayerCaps.MaxTxMtuSize = 1500;
    linkLayerCaps.MaxRxMtuSize = 1500;
    NetAdapterSetLinkLayerCapabilities(adapter, &linkLayerCaps);

    // C. 設定 Tx/Rx 資料路徑 Capabilities (非常重要)
    NET_ADAPTER_TX_CAPABILITIES txCaps;
    // 使用 Fragment Ring 模式，並讓系統管理 payload
    NET_ADAPTER_TX_CAPABILITIES_INIT_FOR_FRAGMENT_RING(&txCaps); 
    
    NET_ADAPTER_RX_CAPABILITIES rxCaps;
    // 推薦：讓作業系統(NetAdapterCx)自動幫你分配 Rx Buffer，你只要負責把 WHD 拿到的資料 Copy 進去
    NET_ADAPTER_RX_CAPABILITIES_INIT_SYSTEM_MANAGED(&rxCaps, 1500 + 14); // MTU + Ethernet Header

    NetAdapterSetDataPathCapabilities(adapter, &txCaps, &rxCaps);

    // 啟動 Adapter
    status = NetAdapterStart(adapter);
    
    return status;
}
```

#### 3. 建立 Tx Queue 與 Rx Queue

NetAdapterCx 負責管理 Queue，我們只需實作 Queue 的 Advance (處理封包) 與 Cancel 回呼。

```c
NTSTATUS
EvtAdapterCreateTxQueue(
    _In_ NETADAPTER Adapter,
    _Inout_ NETTXQUEUE_INIT* TxQueueInit
)
{
    NET_PACKET_QUEUE_CONFIG queueConfig;
    NET_PACKET_QUEUE_CONFIG_INIT(&queueConfig, EvtTxQueueAdvance, EvtTxQueueCancel, EvtTxQueueSetNotificationEnabled);

    NETPACKETQUEUE txQueue;
    NTSTATUS status = NetTxQueueCreate(TxQueueInit, WDF_NO_OBJECT_ATTRIBUTES, &queueConfig, &txQueue);
    return status;
}

// RxQueue 同理，呼叫 NetRxQueueCreate...

// --- Tx 處理核心 (從 Queue 拿 Packet 送給 WHD) ---
VOID EvtTxQueueAdvance(_In_ NETPACKETQUEUE TxQueue)
{
    NET_RING_COLLECTION const * ringCollection = NetTxQueueGetRingCollection(TxQueue);
    NET_RING * packetRing = NetRingCollectionGetPacketRing(ringCollection);
    NET_RING * fragmentRing = NetRingCollectionGetFragmentRing(ringCollection);

    while (packetRing->OSIndex != packetRing->NextIndex) {
        // 取得當前封包
        NET_PACKET* packet = NetRingGetPacketAtIndex(packetRing, packetRing->OSIndex);
        
        // 取得該封包的第一個 Fragment (乙太網通常一個 Packet 只有一個 Fragment)
        NET_FRAGMENT* fragment = NetRingGetFragmentAtIndex(fragmentRing, packet->FragmentIndex);
        
        void* dataBuffer = NetExtensionGetFragmentVirtualAddress(&MyVirtualAddressExtension, fragment->Index);
        SIZE_T dataLength = fragment->ValidLength;

        // 【關鍵】在這裡把 dataBuffer 透過 WHD (whd_network_send_ethernet_data 等) 透過 SDIO 送出去
        WHD_Send_To_Firmware(dataBuffer, dataLength);

        // 標記完成
        packetRing->OSIndex = NetRingIncrementIndex(packetRing, packetRing->OSIndex);
    }
}
```

#### 4. Link Up / Down 通知時機

`NetAdapterSetLinkState` 不能在 `EvtDriverDeviceAdd` 剛建好 Adapter 時就報 Up。
**呼叫時機**：當 WHD 成功 Join AP 並取得 IP 前夕（或 WHD 回報 `WLC_E_LINK` event 為 Up 時）。

```c
VOID NotifyLinkState(NETADAPTER Adapter, BOOLEAN IsUp)
{
    NET_ADAPTER_LINK_STATE linkState;
    NET_ADAPTER_LINK_STATE_INIT(
        &linkState,
        1000000000ull, // 假裝 1Gbps Tx，或者回報真實 WiFi MCS 速率
        1000000000ull, // 假裝 1Gbps Rx
        IsUp ? MediaConnectStateConnected : MediaConnectStateDisconnected,
        MediaDuplexStateFull);

    NetAdapterSetLinkState(Adapter, &linkState);
}
// 當 WHD API (例如 whd_wifi_join) 返回 WHD_SUCCESS 後，呼叫 NotifyLinkState(adapter, TRUE);
```

### B. 韌體資源 (`whd_resource_source_t`) 實作

WHD 需要載入三種資源：`.bin` (FW 主體), `.clm_blob` (地區頻段資料), `.txt` (NVRAM)。

#### 1. 儲存方式：PE Resource (.rc) vs File System (`ZwReadFile`)

| 方式 | 實作難度 | 優點 | 缺點 | 在 Kernel 的可行性 |
| :--- | :--- | :--- | :--- | :--- |
| **PE Resource (.rc)** | **極低** (強烈建議) | 韌體跟著 `.sys` 走，不需擔心早期開機時檔案系統還沒掛載 (C槽還沒 ready) 的問題。指標直接指到 NonPagedPool 即可。 | `.sys` 檔案會變大 (增加約 500KB+)。換韌體必須重新編譯 Driver。 | **極佳**。可用 `MmGetSystemAddressForMdlSafe` 或直接讀取。 |
| **ZwReadFile** | **高** | 隨時可以替換 `C:\Windows\System32\drivers\xxx.bin`，方便測試不同韌體。 | 必須在 `PASSIVE_LEVEL` 執行，且需處理檔案系統掛載時序問題 (通常要延遲初始化或放在 WorkItem)。 | **可行但麻煩**。需確保開機過程中讀取時不發生 BSOD。 |

**結論：對於 Pi 等 ARM64 開發，初期絕對建議使用 PE Resource。** 
你可以寫一個小腳本，把 `.bin` 轉成 C 陣列 (例如 `#include "fw_43455.h"`)，或是放在 `.rc` 檔用 `WdfRegistryQueryMemory` / `ExAllocatePool` 載入。

#### 2. `whd_resource_size` / `whd_get_resource_block` 實作

WHD 在載入韌體時，為了避免一次占用太多記憶體，會一塊一塊 (Block) 跟你討資料。
假設你已經把 `.bin` 放進記憶體陣列 `const uint8_t fw_bin_data[]`。

```c
#define WHD_RESOURCE_BLOCK_SIZE 512 // 或者 4096，看 WHD 的設定

uint32_t my_whd_resource_size(whd_driver_t whd_drv, whd_resource_type_t resource, uint32_t* size_out)
{
    if (resource == WHD_RESOURCE_WLAN_FIRMWARE) {
        *size_out = sizeof(fw_bin_data);
        return WHD_SUCCESS;
    }
    // 處理 NVRAM, CLM_BLOB...
    return WHD_UNSUPPORTED;
}

uint32_t my_whd_get_resource_block(whd_driver_t whd_drv, whd_resource_type_t type,
                                   uint32_t blockno, const uint8_t** data, uint32_t* size_out)
{
    const uint8_t* source_data = NULL;
    uint32_t total_size = 0;

    if (type == WHD_RESOURCE_WLAN_FIRMWARE) {
        source_data = fw_bin_data;
        total_size = sizeof(fw_bin_data);
    } // 判斷其他 type...

    uint32_t offset = blockno * WHD_RESOURCE_BLOCK_SIZE;
    
    if (offset >= total_size) {
        return WHD_BADARG; // 已經讀到底了
    }

    *data = &source_data[offset];
    
    // 計算這次要給多大 (如果剩下不足一個 Block，就給剩下的)
    *size_out = total_size - offset; 
    if (*size_out > WHD_RESOURCE_BLOCK_SIZE) {
        *size_out = WHD_RESOURCE_BLOCK_SIZE;
    }

    return WHD_SUCCESS;
}
```
**注意要點：**
*   **Alignment**：SDIO 傳輸對記憶體對齊有要求。如果你的陣列是直接從 PE 載入的唯讀段 (Read-Only Data)，SDIO DMA 可能會失敗！**保險做法**是：如果 WHD 直接拿 `*data` 指標去做 DMA，你必須確保這些資料位於 **Non-Paged Pool 且 Cache-Aligned**。若 WHD 內部有自己做 Bounce Buffer (複製一次再送)，則給唯讀指標沒關係。

#### 3. NVRAM `.txt` 在 Windows 端的預處理

**強烈建議：在 Windows 外部先「預處理」好，不要在 Kernel 裡直接餵 Raw Text。**

Pi 的原始 NVRAM 長這樣：
```text
# This is a comment
macaddr=00:11:22:33:44:55
sromrev=11
boardrev=0x1304
```

WHD/Broadcom 晶片實際需要的 NVRAM 格式是**「去掉註解、去掉換行，改以 `\0` (NULL) 分隔，最後用兩個 `\0\0` 結尾」的二進位字串池**。

如果你把 Raw `.txt` 丟給 WHD，WHD 內部如果有開啟字串解析引擎，它會嘗試在 CPU 端做字串處理 (strtok 等)。但在 Windows KMDF 環境中做 ASCII 字串解析非常容易踩坑（例如 IRQL 問題、字串函式庫支援度）。

**預處理步驟 (在 Linux/Python 寫個腳本)：**
1. 刪除所有空行和以 `#` 開頭的行。
2. 把每一行的換行符號 `\n` 取代成 `\0` (0x00)。
3. 在整個檔案的最末端補上第二個 `\0` (0x00)，代表結尾。
4. 將這個處理過的二進位檔轉成 C byte array (`nvram_data[]`)。

在 `whd_get_resource_block` 中，當 `type == WHD_RESOURCE_NVRAM` 時，直接把這個預處理過、純粹由 `\0` 分隔的陣列丟給 WHD，這樣能避開 Kernel 中不必要的字串解析風險，成功率最高。
