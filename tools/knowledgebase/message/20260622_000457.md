RESPONSE
========================================================================
這是一個非常經典且具挑戰性的 Windows 驅動開發任務。開發 Windows Bluetooth Extensible Transport Driver（基於 `bthx.h`）來橋接 `bthport.sys` 與底層 UART（H4 協定），核心在於**非同步 I/O 的狀態機管理**與** Broadcom 特殊的 Firmware Download 流程**。

以下是具體的實作指南、程式骨架與架構圖：

---

### 1. 向 bthport 註冊 (Device Stack & INF)

**機制**：你的 driver 是 FDO (Function Driver)，`bthport.sys` 是 Upper Filter。
你不需要手動呼叫 `WdfDeviceCreateDeviceInterface` 建立特製 GUID，而是透過 **INF 檔案** 的宣告，讓 Windows PnP Manager 自動把 `bthport.sys` 疊在你的 driver 上面。

*   **Devnode Tree 位置**：
    ```text
    [ACPI\BCM2E40] (或其他 ACPI ID)
      -> 底層 UART Bus (SerCx2 / serial.sys) 提供 UART Resource
      -> [Your KMDF Transport Driver.sys] (FDO)  <-- 你在這裡
      -> [BTHPORT.sys] (Upper Filter)
      -> [BTHENUM.sys]
    ```
*   **INF 寫法關鍵**：
    必須設定 `Class=Bluetooth` 與 `ClassGuid={e0cbf06c-cd8b-4647-bb8a-263b43f0f974}`。
    透過 `Include=bthtransport.inf` 與 `Needs=BthTransport.NT` 來自動掛載 bthport 相關的 inbox 元件。*(需查閱 WDK 最新藍牙 INF 規範)*

---

### 2. bthx IOCTL 處理模式 (核心邏輯)

`bthport.sys` 會透過 `IRP_MJ_DEVICE_CONTROL` 下發定義在 `bthx.h` 的 IOCTLs。
你需要建立一個 Default Queue 來攔截這些 IOCTL。

#### (1) IOCTL_BTHX_QUERY_CAPABILITIES / SET_VERSION
*   **觸發時機**：Device Start (D0Entry) 之後，bthport 會立刻查詢。
*   **實作骨架**：
    ```c
    // 需查 bthx.h 確認 BTHX_CAPABILITIES 結構
    BTHX_CAPABILITIES caps = {0};
    caps.MaxAclTransferInSize = 1021;  // 需實機確認 CYW43455 的 buffer size
    caps.MaxAclTransferOutSize = 1021;
    caps.MaxScoTransferInSize = 255;
    caps.MaxScoTransferOutSize = 255;
    caps.MaxCommandTransferSize = 255;
    // 回傳至 WdfRequest...
    ```

#### (2) IOCTL_BTHX_WRITE_HCI
*   **觸發時機**：bthport 想發送 HCI Command 或 ACL Data。
*   **實作重點**：`bthx.h` 傳來的結構（`BTHX_HCI_READ_WRITE_CONTEXT`）**沒有 H4 Type byte (0x01/0x02/0x03/0x04)**。你必須自己分配新 Buffer，塞入 1 byte H4 Type，再加上 Payload，然後寫入 UART。
*   **建議模式**：Asynchronous（不建議阻塞 bthport）。

    ```c
    // Write 處理骨架
    PBTHX_HCI_READ_WRITE_CONTEXT ctx = NULL;
    WdfRequestRetrieveInputBuffer(Request, sizeof(BTHX_HCI_READ_WRITE_CONTEXT), &ctx, NULL);

    // 1. Allocate memory for [H4_TYPE (1 byte)] + [HCI Payload]
    // 2. if (ctx->Type == BthX_Hci_Command) H4_TYPE = 0x01;
    // 3. RtlCopyMemory(...);
    // 4. Format WDFIOTARGET write request to UART.
    // 5. 設定 Completion Routine，在裡面呼叫 WdfRequestComplete(Request)
    ```

#### (3) IOCTL_BTHX_READ_HCI (最關鍵的 Pended-Read 模式)
*   **觸發時機**：bthport 會「**預先下發多個 (通常是 2~4 個) Read IRPs**」給你，並把它們 Pend 著。當你從 UART 收到完整的 HCI packet 後，挑一個 pended IRP，填入資料並 Complete。
*   **實作方式**：建立一個 **WDF Manual Queue** 來存放這些 Request。

    ```c
    // 在 EvtIoDeviceControl 中：
    case IOCTL_BTHX_READ_HCI:
        // 直接將 bthport 下發的 Read Request 轉交給 Manual Queue 存放
        status = WdfRequestForwardToIoQueue(Request, DevContext->PendedReadQueue);
        if (!NT_SUCCESS(status)) { WdfRequestComplete(Request, status); }
        break;
    ```
    *當你的 UART Read Pump 收到完整封包時（見下節）：*
    ```c
    // 你的 UART H4 Parser 收集完一個完整 Packet 時呼叫：
    status = WdfIoQueueRetrieveNextRequest(DevContext->PendedReadQueue, &bthxReq);
    if (NT_SUCCESS(status)) {
        // 複製 Payload 到 bthxReq 的 BTHX_HCI_READ_WRITE_CONTEXT (去除 H4 type byte)
        // 需查 bthx.h 確認回傳的 length 是否要包含 header
        WdfRequestCompleteWithInformation(bthxReq, STATUS_SUCCESS, ReturnLength);
    } else {
        // 警告：bthport 沒有給足夠的 Read IRP，你必須把 Packet 暫存在 Driver 的 Ring Buffer 中 (需實機 debug 調整)
    }
    ```

### 3. 下緣接 UART (SerCx2 / serial.sys) 與 Broadcom Init

#### (1) 開啟 UART IoTarget
*   在 `EvtDevicePrepareHardware` 中，解析 `WdfCmResourceList`，找到 `CmResourceTypeConnection` (Serial)。
*   使用 `RESOURCE_HUB_CREATE_PATH_FROM_ID` 巨集將 Connection ID 轉為 Device Path 字串。
*   使用 `WdfIoTargetOpen` 搭配 `WDF_IO_TARGET_OPEN_PARAMS_INIT_OPEN_BY_NAME` 開啟底層 UART。

#### (2) 常駐 Read Pump (H4 Parser) 與非同步讀取
藍牙 H4 協定是串流 (Stream)，UART 不會告訴你封包邊界，你必須自己組裝 (Reassemble)。
*   **機制**：使用 Async Read IRP 加上 State Machine。
*   **狀態機設計**：
    1.  `STATE_READ_TYPE`: 發送 1 byte read request 到 UART -> 決定是 ACL (0x02) 還是 Event (0x04)。
    2.  `STATE_READ_HEADER`: 依據 Type 讀取固定長度 Header (Event 是 2 bytes, ACL 是 4 bytes)。從 Header 解析出 Payload Length。
    3.  `STATE_READ_PAYLOAD`: 讀取 Payload Length 的資料。
    4.  完成一個 Packet -> 去 `PendedReadQueue` 抓一個 Request 來 Complete -> 回到 `STATE_READ_TYPE`。
*   *(需實機)* UART 讀取極度建議使用 `WdfIoTargetFormatRequestForRead` + `WdfRequestSend` 的非同步 Completion Routine，否則會吃死 CPU。

#### (3) Broadcom Vendor Init (Firmware Load)
CYW43455 在上電時只具備 ROM code，必須下載 `.hcd` 韌體才能正常運作。
*   **衝突點**：bthport 假設 Transport Ready 時就已經可以發標準 HCI 指令。但你要先載入韌體。
*   **解法**：在 `EvtDeviceD0Entry` 中，阻擋 D0Entry 的完成（或發派 WDFWORKER）。
    1.  在 Worker Thread 內部開啟 UART。
    2.  設定 UART Baud Rate 為 115200 (預設)。
    3.  發送 BCM 專用 HCI 指令：`HCI_UPDATE_BAUDRATE` (例如提速到 3000000)。
    4.  使用 IOCTL 將底層 UART Baud Rate 也切換到 3000000。
    5.  解析 `.hcd` 檔 (通常掛在 Driver 內部資源或磁碟)，透過 HCI 發送 `HCI_DOWNLOAD_MINIDRIVER`。
    6.  等待 BCM 重啟完成 (收到特定 Event)。
    7.  啟動 Read Pump。
    8.  完成 `EvtDeviceD0Entry`。*(此時 bthport 才會開始發 IOCTL_BTHX_*)*。

### 4. 整體 WDF 物件圖與資料流

```text
[BTHPORT.SYS]
    | (IOCTL_BTHX_WRITE_HCI / READ_HCI)
    V
+-----------------------------------------------------------------------------------+
|  KMDF Transport Driver (bthx)                                                     |
|                                                                                   |
|  [WDFDEVICE]                                                                      |
|       |                                                                           |
|       +-- [WDFQUEUE (Default)]                                                    |
|       |     (Handles Capabilities, Init, Write_HCI)                               |
|       |                                                                           |
|       +-- [WDFQUEUE (Manual)] <------------+                                      |
|       |     (Holds Pended READ_HCI Req)    | (Matches complete packet             |
|       |                                    |  with a pended Read Request)         |
|       |                                    |                                      |
|       +-- [H4 State Machine Context] ------+                                      |
|       |     (Buffer: Type->Header->Payload)|                                      |
|       |                                    |                                      |
|       +-- [WDFREQUEST (Read Pump)] --------+                                      |
|       |     (Loops continuously:           |                                      |
|       |      Completion Routine -> Send Next)                                     |
|       |                                                                           |
|       +-- [WDFWORKER (FW Load)]                                                   |
|             (Used only in D0Entry to parse .hcd and init BCM)                     |
|                                                                                   |
|       +-- [WDFIOTARGET (UART)]                                                    |
+-----------------|--------------------------|--------------------------------------+
                  | (WdfIoTargetSend...)     | (Async Read / Write)
                  V                          V
               [SerCx2 / serial.sys / UART Hardware Controller]
```

### 開發與 Debug 建議 (需實機)
1.  **韌體載入除錯**：CYW43455 的 Baudrate switch 如果有一端沒切好，後面的 `.hcd` 載入會全部 Timeout。建議先寫一支 User-mode App 打開 COM port 測試 BCM init 流程，確保流程正確再塞入 KMDF。
2.  **Ring Buffer**：在高速藍牙（如 A2DP / LE 掃描）時，UART 來的資料可能比 bthport 下發 Read IRP 的速度快。如果你的 `PendedReadQueue` 空了，請務必實作一個軟體 Ring Buffer 暫存從 UART 收到的完整 HCI Packet，否則會掉包（Dropped Packets）。
3.  **Trace Logging (WPP)**：非常關鍵！一定要在 `EvtIoDeviceControl` (收到 BTHX) 和 Read Pump (收到 UART bytes) 加上 WPP 打印，以驗證 H4 Type 和 Payload 長度解析是否正確。
