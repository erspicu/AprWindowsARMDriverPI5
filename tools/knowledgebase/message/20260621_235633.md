這是一項極具挑戰性且非常硬核（Hardcore）的移植工作。將純 C 的 RTOS/Linux 風格 Wi-Fi Host Driver (WHD) 塞進 Windows WDK 的 `/kernel` 環境，會遇到編譯器行為差異與核心限制。

以下為 **Phase A（Build 整合）** 與 **Phase B（連線流程與憑證）** 的具體做法與避坑指南：

---

### A. Build 整合 (WHD + KMDF)

#### 1. 整合形式：直接 Source Inclusion 還是 Static Lib？
**強烈建議：直接把 WHD 的 `.c` 檔案逐一加進你的 KMDF 專案（MSBuild `.vcxproj` 或 WDK CMake）一起編譯。**
*   **為什麼不推薦 Static `.lib`**：如果你用標準的 CMake 去把 WHD 編成 `.lib`，它預設會使用 User-mode 的編譯參數（依賴 MSVCRT、啟用 Floating Point、不同的 Calling Convention）。當你把這個 `.lib` 連結到 `/kernel` 的 `.sys` 時，會爆出海量的 `LNK2019` (Unresolved External Symbol) 或更慘的 runtime Bugcheck（例如在核心層觸發浮點運算例外）。
*   **具體做法**：在 VS 專案中建立一個資料夾 `WHD_Source`，把需要的 `.c` 放進去。WDK 的編譯系統會自動對這些檔案套用 `/kernel`、`/Gz` (如果 x86)、以及核心專用的 Pool Tagging 機制。

#### 2. 核心態的 C 標準庫 (CRT Stubbing)
WDK 的 `/kernel` 模式**沒有**傳統的 C 執行階段 (CRT)。WHD 預期會有標準 C 函式，你必須做映射 (Mapping) 或 Wrapper：
*   **基本型別與標頭檔**：`<stdint.h>`、`<stdbool.h>` 在現代 MSVC (WDK) 中是存在的，直接 Include 不會炸。
*   **記憶體配置 (malloc/free)**：
    WHD 通常會呼叫 OS 抽象層的 `cy_rtos_malloc` 等。你必須將其對應到 KMDF 的 API：
    ```c
    // 實作 WHD 要求的 OS Porting Layer
    void* cy_rtos_malloc(size_t size) {
        // WDK Windows 10 2004 以後強制使用 ExAllocatePool2
        return ExAllocatePool2(POOL_FLAG_NON_PAGED, size, 'DHWw'); // 'DHWw' 是 Pool Tag
    }
    void cy_rtos_free(void* ptr) {
        if (ptr) ExFreePoolWithTag(ptr, 'DHWw');
    }
    ```
*   **記憶體操作 (memcpy/memset)**：
    在 KMDF 中 `#include <ntddk.h>`，它會將 `memcpy` 巨集映射到 `RtlCopyMemory`，`memset` 映射到 `RtlFillMemory`，`memcmp` 映射到 `RtlCompareMemory`。這部分通常直接過關，不用自己刻。
*   **字串操作與 snprintf**：
    **這是一個大坑。** WHD 的 log 系統會大量使用 `snprintf`。核心態不支援 `snprintf`，你必須自己寫一個 Stub 導向 `RtlStringCchPrintfA` (ANSI 字串)。
    ```c
    #include <ntstrsafe.h>
    // 標註不確定處：WHD 如果預期 snprintf 回傳寫入字元數，RtlStringCchPrintfA 回傳的是 NTSTATUS，必須轉換！
    int snprintf(char* buffer, size_t count, const char* format, ...) {
        va_list args;
        va_start(args, format);
        // 注意：RtlStringCbVPrintfA 才是對應 vsnprintf 的安全函數
        NTSTATUS status = RtlStringCbVPrintfA(buffer, count, format, args);
        va_end(args);
        return NT_SUCCESS(status) ? (int)strlen(buffer) : -1; 
    }
    ```

#### 3. WHD 的 Config / Component Macros
你需要透過 Preprocessor `#define` 來閹割掉 WHD 預設的 RTOS 行為，並指定硬體。通常在編譯選項 (`Project Properties -> C/C++ -> Preprocessor`) 中加入：
*   `WHD_BUS_SDIO`：指定使用 SDIO 匯流排。
*   `WLAN_CHIP_43455` 或類似的型號 ID (需查閱你的 WHD 版本原始碼中的 Makefile/CMakeLists.txt，有時寫作 `CYW43455`)。
*   `WHD_CUSTOM_HAL` 或 `WHD_USE_CUSTOM_OS_LAYER` (依版本而異)：這會告訴 WHD 「不要嘗試包含 FreeRTOS 或 ThreadX 的標頭檔，我會自己提供 `whd_network_api.h` 和 `cy_rtos_api.h` 的實作」。
*   `WHD_NO_ASSERT` 或改寫 Assert：Windows Kernel 的 `ASSERT()` 會在 checked build 觸發藍白畫面，如果 WHD 的 assert 條件寫得比較隨意，最好將其對應到 `DbgPrint` 加上 `DbgBreakPoint()`，而不是直接 BSOD。

#### 4. 編譯地雷 (MSVC /kernel vs GCC)
*   **__attribute__((packed)) 炸彈**：
    WHD 原碼中會定義很多硬體暫存器和封包結構體。GCC 用 `__attribute__((packed))`，MSVC 不吃這個。
    **具體解法**：WHD 通常會有一個編譯器抽象層（例如 `whd_compiler.h` 中的 `WHD_PACKED`）。你必須修改它為 MSVC 的格式：
    ```c
    /* 在 MSVC 區塊下這樣定義 */
    #define WHD_PACK_START __pragma(pack(push, 1))
    #define WHD_PACK_END   __pragma(pack(pop))
    // 若原始碼硬寫 __attribute__((packed))，你只能用腳本全局替換。
    ```
*   **浮點運算 (Floating Point)**：
    WDK `/kernel` 下出現 `float` 或 `double` 會報編譯錯誤 `C2812`。一般 Wi-Fi 驅動很少算浮點，但如果在某些 Throughput 統計函數裡有除法轉浮點，**必須改成整數運算**。
*   **可變長度陣列 (VLAs)**：
    MSVC 不支援 C99 的 `int array[variable];`。如果 WHD 源碼中有，編譯會報錯。
    **解法**：改用 `cy_rtos_malloc` 動態配置，或者給一個 `MAX_SIZE` 的靜態陣列。

### B. 連線流程與憑證

因為你跳過了 Windows WDI 原生的 Wi-Fi AutoConfig 框架，把網卡偽裝成 Ethernet，所以你必須在 Driver 內部自己處理 SSID 與密碼的取得與連線。

#### 1. SSID/Password 的取得最務實做法
**建議放 Registry 的 Parameters Key。**
*   **位置**：`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Services\<YourDriverName>\Parameters`
*   **讀取時機**：在 `EvtDevicePrepareHardware` 或 `EvtDeviceD0Entry` 階段讀取。
*   **實作方法**：
    ```c
    WDFKEY hKey = NULL;
    NTSTATUS status = WdfDriverOpenParametersRegistryKey(WdfGetDriver(), STANDARD_RIGHTS_ALL, WDF_NO_OBJECT_ATTRIBUTES, &hKey);
    if (NT_SUCCESS(status)) {
        DECLARE_CONST_UNICODE_STRING(ssidValName, L"TargetSSID");
        DECLARE_CONST_UNICODE_STRING(pwdValName, L"TargetPassword");
        
        WDFSTRING ssidWdfStr, pwdWdfStr;
        WdfStringCreate(NULL, WDF_NO_OBJECT_ATTRIBUTES, &ssidWdfStr);
        WdfRegistryQueryString(hKey, &ssidValName, ssidWdfStr);
        // ... 同理讀取密碼
    }
    ```
*   **格式轉換地雷 (UTF-16 vs UTF-8)**：
    Windows Registry 讀出來是 UTF-16 (`UNICODE_STRING` / `WCHAR`)。但 **WHD 預期 SSID 和 Password 是單字節的 ASCII 或 UTF-8**！你必須用核心函數 `RtlUnicodeStringToUTF8String` (如果 WDK 較新支援) 或 `RtlUnicodeStringToAnsiString` 把 `WCHAR` 轉成 `char*`，否則 WHD 拿到的字串都是 `S\0S\0I\0D\0`，絕對連不上。

#### 2. 連線流程：Scan 還是直接 Join？
*   **最務實的做法：Direct Join (直接連線)**。
    若 AP 已經明確知道，先 Scan 只是徒增複雜度（還得處理 Scan Result Callback）。直接呼叫 `whd_wifi_join`。
*   **`whd_security_t` 怎麼選**：
    通常你的 IoT/Embedded 路由器是 WPA2。
    使用 `WHD_SECURITY_WPA2_AES_PSK`。
    如果你的 WHD FW 太舊不支援 WPA3，傳 WPA3 會直接回傳錯誤。除錯初期建議先將 AP 設為 Open (`WHD_SECURITY_OPEN`) 測試 TX/RX 是否打通，再掛 WPA2 測試 WHD 內建的 WPA Supplicant 握手是否正常。

#### 3. 狀態機與 NetAdapterCx 聯動 (Link State)
因為 Wi-Fi 會斷線，你不能在 KMDF PnP Callback 裡死等 (Block) 連線成功。
*   **啟動連線**：
    在 `EvtDeviceD0Entry` 中，啟動一個 **WdfWorkItem** (系統工作執行緒)。在這個 WorkItem 裡面呼叫 `whd_wifi_join`。
*   **向 OS 報備狀態 (NetAdapterSetLinkState)**：
    1.  初始化時先報 Down：
        ```c
        NET_ADAPTER_LINK_STATE linkState;
        NET_ADAPTER_LINK_STATE_INIT_DISCONNECTED(&linkState);
        NetAdapterSetLinkState(adapter, &linkState);
        ```
    2.  WorkItem 裡的 `whd_wifi_join` 若回傳 `WHD_SUCCESS`，更新為 Up：
        ```c
        NET_ADAPTER_LINK_STATE_INIT(&linkState, 
                                    NDIS_LINK_SPEED_UNKNOWN, 
                                    MediaConnectStateConnected, 
                                    MediaDuplexStateHalf, 
                                    NetAdapterPauseFunctionTypeUnsupported, 
                                    NetAdapterAutoNegotiationFlagNone);
        NetAdapterSetLinkState(adapter, &linkState);
        ```
*   **斷線處理與監聽 Callback**：
    你必須註冊 WHD 的非同步事件：
    ```c
    whd_management_set_event_handler(ifp, event_types, my_whd_event_handler, context, &event_idx);
    ```
    當 `my_whd_event_handler` 收到 `WLC_E_LINK` (Link Down) 或 `WLC_E_DEAUTH` 時：
    1. 呼叫 `NetAdapterSetLinkState` 報 Down (切斷 Windows IP 協議棧的傳輸)。
    2. **不要在 Callback 裡直接重連**（Callback 所在的 IRQL 可能是 `DISPATCH_LEVEL`，而連線需要 Sleep 和 IO）。
    3. 把 "重連請求" 排入一個 `WdfWorkItem`，在 WorkItem 中實作一個 Retry 迴圈（例如先 `KeDelayExecutionThread` 等 3 秒，再呼叫 `whd_wifi_join`），直到重新連上為止。
