### 1. BCM Vendor HCI Opcodes (CYW43455)

UART 傳輸層採用 H4 協定（第一 byte：`0x01`=Command, `0x04`=Event）。以下 Opcode 皆為 16-bit，Little-Endian 送出時低位元組在前。
Standard HCI OGF = 0x03, Vendor OGF = 0x3F (0xFC)。

| 命令名稱 | OGF | OCF | Opcode (16-bit) | 參數長度 | Payload 格式 (Bytes) | 說明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **HCI_Reset** | 0x03 | 0x0003 | **0x0C03** | 0 | `無` | 標準重啟。H4 送出 `0x01 0x03 0x0C 0x00` |
| **Download_Minidriver** | 0x3F | 0x002E | **0xFC2E** | 0 | `無` | 讓晶片停止目前韌體，進入準備收 `.hcd` 的模式。H4 送出 `0x01 0x2E 0xFC 0x00` |
| **Write_RAM** | 0x3F | 0x004C | **0xFC4C** | N | `Data (由 .hcd 提供)` | 你**不需要**手動組裝此命令，它直接以 Record 形式寫死在 `.hcd` 檔內。 |
| **Launch_RAM** | 0x3F | 0x004E | **0xFC4E** | 4 | `0xFF 0xFF 0xFF 0xFF` | 執行載入的韌體並軟重啟晶片。 |
| **Update_Baud_Rate**| 0x3F | 0x0018 | **0xFC18** | 6 | `0x00 0x00 [Baud 4-bytes LE]` | 例如設 3,000,000 (0x002DC6C0)：<br>`0x00 0x00 0xC0 0xC6 0x2D 0x00` |
| **Write_BD_ADDR** | 0x3F | 0x0001 | **0xFC01** | 6 | `[MAC Address 6-bytes 反序]`| 例如 MAC `11:22:33:44:55:66`，Payload 為：<br>`0x66 0x55 0x44 0x33 0x22 0x11` |

### 2. `.hcd` 檔格式與解析虛擬碼

**.hcd 結構非常純粹**，它就是「一連串可以直接當作 HCI Command 送出的二進位紀錄」。
每筆 Record 的結構：`[Opcode (2 bytes LE)] [Length (1 byte)] [Data (Length bytes)]`。
*註：.hcd 內部沒有 H4 的 `0x01` 標頭，你需要自己加上。*

**解析與傳送虛擬碼：**
```c
// 假設 hcd_buffer 包含整個檔案，hcd_size 為檔案大小
uint8_t* ptr = hcd_buffer;

while (ptr < hcd_buffer + hcd_size) {
    uint16_t opcode = ptr[0] | (ptr[1] << 8); // 讀取 Opcode (通常是 0xFC4C)
    uint8_t param_len = ptr[2];               // 讀取長度
    uint8_t* payload = &ptr[3];               // 指向資料
    
    // 1. 組裝 H4 封包
    uint8_t h4_packet[256];
    h4_packet[0] = 0x01; // H4 Command
    h4_packet[1] = ptr[0];
    h4_packet[2] = ptr[1];
    h4_packet[3] = param_len;
    memcpy(&h4_packet[4], payload, param_len);
    
    // 2. 透過 UART 送出 h4_packet (長度為 param_len + 4)
    Uart_Send(h4_packet, param_len + 4);
    
    // 3. 等待 Command Complete Event (0x04 0x0E 0x04 0x01 [OP L] [OP H] [Status])
    // ！！！地雷警告：必須等這包 Complete 收完，才能送下一筆，否則晶片會當機！！！
    Status = Uart_WaitCommandComplete(opcode, TIMEOUT_1000_MS);
    if (!NT_SUCCESS(Status)) break;
    
    // 推進指標
    ptr += (3 + param_len);
}
```

### 3. 完整 Init 序列與 Timing 地雷

從上電到 Ready 的時序非常嚴格，以下是經過無數次硬體驗證的流程：

1. **(Host)** 開啟 UART，初始 Baud rate 設為 `115200`，無 Flow Control (或 RTS/CTS 設為 False)。
2. **送 HCI_Reset (0x0C03)** → 等 Cmd Complete。
3. **送 Download_Minidriver (0xFC2E)** → 等 Cmd Complete。
   * **[Timing 地雷]** 收到 Complete 後，必須 **Delay 50ms**。讓晶片進入 ROM download mode。
4. **迴圈寫入 `.hcd` 檔** (見上述虛擬碼)。
5. **送 Launch_RAM (0xFC4E)** (Payload `0xFF 0xFF 0xFF 0xFF`) → 等 Cmd Complete。
   * **[Timing 地雷]** 晶片此時會軟重啟執行新韌體。必須 **Delay 250ms ~ 500ms**。
   * *注意：重啟後，晶片的 Baud rate 會**強制切回預設的 115200***。
6. **再次送 HCI_Reset (0x0C03)** → 等 Cmd Complete (確認新韌體已醒來)。
7. **送 Write_BD_ADDR (0xFC01)** → 等 Cmd Complete (樹莓派通常沒有獨立 EEPROM 存 MAC，靠 OS 寫入或隨機生成)。
8. **送 Update_Baud_Rate (0xFC18)** (設為 3M 或 4M) → 等 Cmd Complete。
   * *這時候 Cmd Complete 是用舊的 `115200` 送回來的。*
9. **(Host) 執行 Baud 切換** (見第4節)。
   * **[Timing 地雷]** 切完後 **Delay 10ms**。
10. **(Host) 啟用 UART Hardware Flow Control (RTS/CTS)**。
11. **(Host)** 準備將 Transport Interface (標準 HCI) 註冊/呈現給上層 `bthport`。

### 4. Host 端 Baud 切換實作 (WDF UART IOCTL)

收到 `Update_Baud_Rate` 的 Command Complete 後，Host UART 必須乾淨俐落地切換，不掉 byte。

```c
// 1. 先 Purge 掉底層 UART 的 TX/RX Buffer (清空 In-flight 雜訊)
ULONG purgeMask = SERIAL_PURGE_RXABORT | SERIAL_PURGE_RXCLEAR | 
                  SERIAL_PURGE_TXABORT | SERIAL_PURGE_TXCLEAR;
WdfIoTargetSendIoctlSynchronously(
    UartIoTarget, NULL, 
    IOCTL_SERIAL_PURGE, 
    &purgeInputMemory, // 包裝 purgeMask
    NULL, NULL, NULL);

// 2. 設定新 Baud Rate
SERIAL_BAUD_RATE baudRate;
baudRate.BaudRate = 3000000; // 3 Mbps

WDF_MEMORY_DESCRIPTOR inputDesc;
WDF_MEMORY_DESCRIPTOR_INIT_BUFFER(&inputDesc, &baudRate, sizeof(baudRate));

NTSTATUS status = WdfIoTargetSendIoctlSynchronously(
    UartIoTarget, NULL, 
    IOCTL_SERIAL_SET_BAUD_RATE, 
    &inputDesc, NULL, NULL, NULL);

// 3. (Optional but Recommended) 設定 Flow Control
SERIAL_HANDFLOW handFlow = {0};
// ... 填充 handFlow 結構以啟用 RTS/CTS (SERIAL_CTS_HANDSHAKE | SERIAL_RTS_CONTROL) ...
WdfIoTargetSendIoctlSynchronously(UartIoTarget, NULL, IOCTL_SERIAL_SET_HANDFLOW, ...);

// 4. 等待一下讓 UART 穩定
KeStallExecutionProcessor(10000); // 10ms
```

### 5. 韌體檔放哪、怎麼讀？

對於 Pi 4 / Pi 5 使用的 CYW43455，正確對應的 firmware 是 **`BCM4345C0.hcd`**。
*(備註：Pi 5 的藍牙晶片有時標記為 Synaptics 晶片，因為 Broadcom IoT 部門被收購，但韌體架構和檔名依舊是 BCM4345C0)*。

**在 Windows 驅動內的最佳實踐：**
不要塞進 PE Resource (因為微軟可能會推驅動更新，但韌體常由 Raspberry Pi Foundation 更新)。請放在 File System 中。

1. **路徑存放**：將 `.hcd` 安裝到 `\SystemRoot\System32\drivers\BCM4345C0.hcd`。
2. **讀取時機**：在 WDF 的 `EvtDevicePrepareHardware` callback 中讀取。此時 IRQL 是 `PASSIVE_LEVEL`，可以使用 `ZwCreateFile` / `ZwReadFile`。
3. **實作方式**：
```c
UNICODE_STRING fwPath;
RtlInitUnicodeString(&fwPath, L"\\SystemRoot\\System32\\drivers\\BCM4345C0.hcd");

OBJECT_ATTRIBUTES objAttr;
InitializeObjectAttributes(&objAttr, &fwPath, OBJ_CASE_INSENSITIVE | OBJ_KERNEL_HANDLE, NULL, NULL);

HANDLE fileHandle;
IO_STATUS_BLOCK ioStatusBlock;
NTSTATUS status = ZwCreateFile(&fileHandle, GENERIC_READ, &objAttr, &ioStatusBlock, 
                               NULL, FILE_ATTRIBUTE_NORMAL, FILE_SHARE_READ, 
                               FILE_OPEN, FILE_SYNCHRONOUS_IO_NONALERT, NULL, 0);

if (NT_SUCCESS(status)) {
    // 取得檔案大小
    FILE_STANDARD_INFORMATION fileInfo;
    ZwQueryInformationFile(fileHandle, &ioStatusBlock, &fileInfo, sizeof(fileInfo), FileStandardInformation);
    
    // 配置 NonPagedPoolNx 記憶體來放韌體
    PVOID fwBuffer = ExAllocatePool2(POOL_FLAG_NON_PAGED, fileInfo.EndOfFile.LowPart, 'DCBH');
    
    // 讀取檔案
    ZwReadFile(fileHandle, NULL, NULL, NULL, &ioStatusBlock, fwBuffer, fileInfo.EndOfFile.LowPart, NULL, NULL);
    ZwClose(fileHandle);
    
    // 現在你可以在 PASSIVE_LEVEL 執行上述的「迴圈寫入」動作了。
}
```

**總結落地建議：**
實作一個獨立的 State Machine (狀態機) 來跑這段 Initialization Sequence。不要用單一巨大的 synchronous thread 阻塞 PnP 過程太久，如果必須同步做，確保你將 WDF 的 `EvtDevicePrepareHardware` Timeout 設定拉長（預設有時會看系統，韌體載入+重啟可能耗時 1~2 秒）。
