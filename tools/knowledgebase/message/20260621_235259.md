### 1. KMDF Function Driver 與 `sdbus.sys` 的列舉關係

*   **INF Hardware ID 怎麼寫？**
    *   SDIO 的 Hardware ID 格式通常為 `SD\VID_xxxx&PID_xxxx&MF_xxxx` 或單純 `SD\VID_xxxx&PID_xxxx`。
    *   CYW43455 的 Broadcom VID 是 `0x02D0`。PID 依據 Firmware 會有不同（通常是 `0x4345` 或 `0xA9BF`，**[需實機/查 datasheet 確認]**）。
    *   INF Match 範例：`%CYW43455.DeviceDesc% = CywWlan_Device, SD\VID_02D0&PID_4345`
*   **Device Setup Class 怎麼設？**
    *   既然你用 NetAdapterCx，Class 必須是 `Net`，GUID 為 `{4d36e972-e325-11ce-bfc1-08002be10318}`。
*   **你的驅動是 FDO 嗎？sdbus 怎麼切 devnode？**
    *   **是，你的 KMDF 驅動會是 FDO (Function Device Object)**。`sdbus.sys` 扮演 Bus Driver (PDO)。
    *   `sdbus.sys` 會為 SDIO 卡上的**每一個 active function 建立獨立的 devnode**。
    *   對於 CYW43455：
        *   **Function 0**：CCCR (由 `sdbus.sys` 掌控，通常不給上層建立 devnode)。
        *   **Function 1**：Backplane 控制與 WLAN 暫存器（你的 Wi-Fi 驅動會綁定到這個 devnode）。
        *   **Function 2**：WLAN Data 傳輸（WHD 實作中，F1 負責控制，F2 負責資料，但 Windows sdbus 可能將 F1/F2 視為同一個網卡實體，或你的驅動只需掛在 F1，並透過 F1 讀寫 F2，**[需實機驗證 sdbus 的行為]**。多數 Broadcom 驅動掛在 F1）。
        *   **Function 3**：Bluetooth (若為 Combo 晶片，會列舉為另一個獨立的藍牙 devnode，掛載 BTH 驅動)。

### 2. 取得 SDBUS_INTERFACE_STANDARD

在 `EvtDevicePrepareHardware` 或 `EvtDriverDeviceAdd` 中，我們需要向底層 PDO 請求 SD Bus 的介面，以獲取 function pointers。

```c
SDBUS_INTERFACE_STANDARD G_SdBusInterface; // 全域或放在 DeviceContext

NTSTATUS GetSdbusInterface(WDFDEVICE Device) {
    NTSTATUS status;
    
    RtlZeroMemory(&G_SdBusInterface, sizeof(SDBUS_INTERFACE_STANDARD));
    G_SdBusInterface.Size = sizeof(SDBUS_INTERFACE_STANDARD);
    G_SdBusInterface.Version = 1;

    // 透過 WDF 向 sdbus.sys (PDO) 查詢 Interface
    status = WdfFdoQueryForInterface(
        Device,
        &GUID_SDBUS_INTERFACE_STANDARD,
        (PINTERFACE)&G_SdBusInterface,
        sizeof(SDBUS_INTERFACE_STANDARD),
        1,
        NULL
    );

    return status;
}
```

**SDBUS_INTERFACE_STANDARD 內重要的 Function Pointers：**
*   `InitializeInterface`：註冊 SDIO Interrupt callback。
*   `SubmitRequest`：核心函數！用來發送 `SDBUS_REQUEST_PACKET` (CMD52/53)，在 PASSIVE_LEVEL 呼叫時通常是**同步**的，不需手動處理 IRP 等待。
*   `GetProperty` / `SetProperty`：用來設定 Bus Width 或 Clock（不直接用 CMD52 寫 CCCR 時的替代方案）。

### 3. & 3.5 SDIO 上線初始化序列 (CCCR CMD52) 與 Packet 填寫

**⚠️ 重要 Windows 特性警告**：
Windows `sdbus.sys` 在載入你的 Function Driver 之前，**通常已經自動完成了 Function 0 (CCCR) 的初始化**（包含 Enable I/O、Enable INT、Set Bus Width）。如果你直接發 RAW CMD52 去寫 CCCR (Function 0)，可能會被 `sdbus.sys` 擋下或造成 BSOD。
但依據你的要求，以下提供**如何透過 SubmitRequest 發送 RAW CMD52 的精簡同步寫法**。

**CMD52 Argument 格式 (32-bit)：**
`[31] R/W | [30:28] Function | [27] RAW | [25:9] Address | [7:0] Data`

```c
// 通用的 CMD52 讀寫 Helper (同步執行)
NTSTATUS SdioCmd52(UINT8 Function, UINT32 Address, UINT8* Data, BOOLEAN isWrite) {
    SDBUS_REQUEST_PACKET packet;
    RtlZeroMemory(&packet, sizeof(packet));

    // 使用標準 Port R/W (sdbus.sys 推薦方式，會自動對應到你當前綁定的 Function)
    // 若要強制發 RAW CMD52 包含 Func 0，需使用 SDRF_DEVICE_COMMAND，但容易被擋。
    // 這裡示範標準寫法：
    packet.RequestFunction = isWrite ? SDRF_WRITE_PORT_UCHAR : SDRF_READ_PORT_UCHAR;
    packet.Parameters.ReadWritePort.Port = Address;
    if (isWrite) {
        packet.Parameters.ReadWritePort.Data = *Data;
    }

    // 同步呼叫 (SubmitRequest 幫你封裝了底層的 IRP 機制)
    NTSTATUS status = G_SdBusInterface.SubmitRequest(G_SdBusInterface.Context, &packet);
    
    if (NT_SUCCESS(status) && !isWrite) {
        *Data = (UINT8)packet.Parameters.ReadWritePort.Data;
    }
    return status;
}

// === SDIO 初始化序列 (通常地址在 Func 0 CCCR) ===
// 註：若用 SDRF_WRITE_PORT_UCHAR 無法指定 Func 0，需改用 G_SdBusInterface.SetProperty
void SdioBringUpSequence() {
    UINT8 val = 0;

    // 1. Enable I/O Function 1 (CCCR Reg 0x02)
    val = (1 << 1); 
    // SdioCmd52(0, 0x02, &val, TRUE); // [需實機確認 sdbus.sys 是否允許操作 Func 0]

    // 2. Polling I/O Ready (CCCR Reg 0x03)
    // do { SdioCmd52(0, 0x03, &val, FALSE); } while(!(val & 0x02));

    // 3. Enable Function Interrupt (CCCR Reg 0x04)
    val = 0x03; // Master INT Enable (Bit 0) | Func 1 INT Enable (Bit 1)
    // SdioCmd52(0, 0x04, &val, TRUE);

    // 4. Set Bus Width to 4-bit (CCCR Reg 0x07)
    val = 0x02; // 0x02 = 4-bit
    // SdioCmd52(0, 0x07, &val, TRUE);

    // 5. 設 Block Size 為 64 Bytes (FBR 區塊, Function 1 的設定在 0x110, 0x111)
    // Block size 64 = 0x0040
    val = 0x40; SdioCmd52(1, 0x110, &val, TRUE); // Low byte
    val = 0x00; SdioCmd52(1, 0x111, &val, TRUE); // High byte
}
```
*(實務上在 Windows 中，Block Size 建議使用 `G_SdBusInterface.SetProperty` 搭配 `SDBUS_PROPERTY_BLOCK_LENGTH` 來設定，讓 Host Controller 同步知道。)*

### 4. 讀取 CYW43455 Chip ID (0x4345)

**原理：**
CYW43455 的 Backplane (內部 AXI 總線) 透過 **Function 1** 來存取。
Chip ID 暫存器的物理位址位於 Backplane 的 `0x1800_0000`。
因為 SDIO 暫存器地址只有 15-bit (0~0x7FFF)，我們必須把位址分為兩部分：
1. **Window Address (高位)**：寫入 Function 1 的 `0x1000A` (Mid-Low), `0x1000B` (Mid-High), `0x1000C` (High)。
2. **Offset (低位)**：固定映射在 Function 1 的 `0x8000` 到 `0xFFFF` 區間。
   `0x18000000` 取 32KB window，Window 設為 `0x180000`，Offset 為 `0x0000`。最終 CMD53 讀取的地址 = Base `0x8000` + Offset `0x0000` = `0x8000`。

```c
// 通用的 CMD53 讀寫 Helper (同步執行)
NTSTATUS SdioCmd53(UINT8 Function, UINT32 Address, UINT8* Buffer, ULONG Length, BOOLEAN isWrite) {
    SDBUS_REQUEST_PACKET packet;
    RtlZeroMemory(&packet, sizeof(packet));

    packet.RequestFunction = isWrite ? SDRF_WRITE_PORT_BUFFER : SDRF_READ_PORT_BUFFER;
    packet.Parameters.ReadWriteBuffer.Port = Address;
    packet.Parameters.ReadWriteBuffer.Buffer = Buffer;
    packet.Parameters.ReadWriteBuffer.Length = Length;

    return G_SdBusInterface.SubmitRequest(G_SdBusInterface.Context, &packet);
}

// 核心里程碑：讀取 Chip ID
NTSTATUS ReadCyw43455ChipId() {
    NTSTATUS status;
    UINT8 val;
    UINT32 chipIdRaw = 0;
    UINT16 chipId = 0;

    // 1. 設定 Backplane Window Address 到 0x18000000
    // Address format: 0x 18 00 00 (High, Mid-High, Mid-Low)
    
    val = 0x00; // Mid-Low
    status = SdioCmd52(1, 0x1000A, &val, TRUE);
    if (!NT_SUCCESS(status)) return status;

    val = 0x00; // Mid-High
    status = SdioCmd52(1, 0x1000B, &val, TRUE);
    if (!NT_SUCCESS(status)) return status;

    val = 0x18; // High
    status = SdioCmd52(1, 0x1000C, &val, TRUE);
    if (!NT_SUCCESS(status)) return status;

    // 2. 透過 CMD53 讀取 4 bytes (Window Base = 0x8000)
    // 這裡我們讀取 0x8000，底層會自動對應到 Backplane 的 0x18000000
    status = SdioCmd53(1, 0x8000, (UINT8*)&chipIdRaw, 4, FALSE);
    if (!NT_SUCCESS(status)) {
        // DbgPrint("CMD53 Read Failed!\n");
        return status;
    }

    // 3. 解析 Chip ID (Broadcom Chipcommon Core 暫存器定義)
    // Chip ID 通常位於讀回來的低 16-bit
    chipId = chipIdRaw & 0xFFFF;

    if (chipId == 0x4345) {
        // SUCCESS! 第一個 Bring-up 里程碑達成！
        // DbgPrint("CYW43455 Chip ID Verified: 0x%04X\n", chipId);
    } else {
        // DbgPrint("Unknown Chip ID: 0x%04X\n", chipId);
    }

    return STATUS_SUCCESS;
}
```

### 總結提示
1. **IRP 的處理**：使用 `SDBUS_INTERFACE_STANDARD` 的 `SubmitRequest` 時，不需要你自己建 `IRP_MJ_INTERNAL_DEVICE_CONTROL` 並呼叫 `KeWaitForSingleObject`。`sdbus.sys` 提供的這個 function pointer 在 PASSIVE_LEVEL 會幫你封裝並**同步 (Synchronous)** 返回結果，這對初期 Bring-up 寫暫存器非常方便。
2. **Backplane 喚醒**：有時候晶片剛上電，Backplane Clock 是關閉的（Sleep mode）。如果在 `SdioCmd53` 讀取 `0x8000` 時卡住或回傳錯誤，可能需要先透過 CMD52 寫入 `0x1000E` (SDIO Core Control) 將 `ALP` 或 `HT` Clock 強制開啟 **[需查 WHD 原始碼 `dhdsdio_clkctl` 相關實作]**。
