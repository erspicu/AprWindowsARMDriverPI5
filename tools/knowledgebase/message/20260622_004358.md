## Response

這是一條硬核但完全可行的路線。繞過 PiSP（硬體 ISP）直接使用 CFE（Camera Frontend）將 RAW 資料透過 PCIe DMA 寫入系統記憶體，然後在 User-mode (DeviceMFT) 進行軟體 ISP。這完全符合 Windows 驅動架構的最佳實踐。

以下是「CFE/CSI-2/sensor 初始化 + AVStream + DeviceMFT」的可落地細節，區分**事實 (Fact)** 與**推測/需確認 (Speculation/Check)**。

---

### 1. Sensor + CSI-2 + RP1 CFE Bring-up

**[Fact] 硬體層級控制流**：Windows ARM64 -> PCIe -> RP1 -> (I2C/GPIO/CFE) -> IMX708。

*   **Sensor (IMX708) I2C 與初始化**：
    *   **I2C 路由**：**[Fact]** 必須走你已經移植的 `rp1-dw-i2c`。在 ACPI/Device Tree 中宣告 Camera 節點相依於 RP1 I2C controller，或者在 Kernel 中透過 `IRP_MJ_INTERNAL_DEVICE_CONTROL` 呼叫 I2C stack。
    *   **初始化序列**：**[Fact]** 直接從 Linux kernel `drivers/media/i2c/imx708.c` 提取 `imx708_mode_common_regs` (基礎設定) 與對應 resolution 的 register array。
    *   **設定重點**：`0x0100` (Mode Select: Standby/Streaming)、`0x0114` (CSI Lane Mode, 2 還是 4 lane)、Exposure/Analog Gain 暫存器。
*   **CSI-2 D-PHY / CFE 設定**：
    *   **資料流**：IMX708 (MIPI) -> RP1 D-PHY -> RP1 CFE -> RP1 AXI/PCIe Bridge -> System RAM。
    *   **暫存器設定 (需查 Linux `rp1-cfe` source)**：
        *   `CFE_CSI2_CTRL`：設定 Lane count (2/4)、Enable CSI-2 RX。
        *   `CFE_CH0_CTRL`：設定 Data Type (RAW10 是 `0x2B`)。
        *   `CFE_CH0_DMA_BASE`：**[關鍵]** 填入 System RAM 的 DMA 目標位址 (IOVA)。
        *   `CFE_CH0_DMA_STRIDE` / `CFE_CH0_FRM_SIZE`：設定每行 byte 數與總大小。
        *   `CFE_IRQ_EN`：開啟 Frame End (FE) 中斷。
    *   **[Fact]** CFE 的行為是 Bus Master DMA，它會把整張 RAW 影像連續寫入你指定的記憶體區塊（Packed RAW10，每 5 bytes 塞 4 個 pixels）。
*   **時脈與電源**：
    *   **[Check]** Sensor Clock (EXTCLK)：通常由 RP1 的 `clk_cam` 產出 24MHz 訊號送到排線。你需要查閱 RP1 Clock manager 暫存器（對應 Linux `clk-rp1.c`）。
    *   **GPIO 控制**：透過 RP1 的 GPIO 控制 Camera 模組的 XSHUTDN (Reset/Power down) 腳位。拉高才能開始 I2C 通訊。

### 2. AVStream Capture Miniport 骨架

**[Fact] AVStream 是 Kernel 負責硬體控制與資料搬運的框架。**

*   **註冊與架構**：
    *   **Device 註冊**：驅動入口呼叫 `KsInitializeDriver`，註冊 `KSCATEGORY_VIDEO_CAMERA` 和 `KSCATEGORY_CAPTURE`。
    *   **Filter/Pin**：定義一個 Capture Pin。
    *   **Format GUID**：因為你要輸出 RAW，Windows 原生不認識 MIPI RAW10。**[Fact]** 你必須定義自訂的 Media Subtype GUID（例如 `MEDIASUBTYPE_RP1_RAW10`）。這個 Format 只會在 Kernel 與你的 DeviceMFT 之間流通，Windows 應用程式不會看到它。
*   **Buffer 流 (DMA -> AVStream)**：
    1.  初始化時，預先分配 WDF Common Buffer (見第 4 節)。
    2.  將 Common Buffer 物理位址寫入 CFE `DMA_BASE` 暫存器。
    3.  CFE 寫完一張畫面 -> 發出 MSI-X 中斷 -> 觸發 ISR -> 觸發 DPC。
    4.  在 DPC 中：
        *   呼叫 `KsPinGetLeadingEdgeStreamPointer` 取得 AVStream 下發的空白 Buffer (KSSTREAM_POINTER)。
        *   **[效能瓶頸點]** 將 Common Buffer 的資料 `RtlCopyMemory` 複製到 KSSTREAM_POINTER 的資料指標中。（更進階的做法是用 Scatter/Gather DMA 直接讓 CFE 寫進 KS Buffer，但第一版強烈建議先用 Common Buffer + Copy，保證能動）。
        *   呼叫 `KsStreamPointerAdvanceOffsetsAndUnlock`，這會把填滿 RAW 資料的 Buffer 往上層 (DeviceMFT) 送。
*   **`ks.h` C++ 坑的具體規避**：
    *   **[Fact]** `ks.h` 裡面充斥著無名 union 和奇葩的 struct packing，用 MSVC C++ 編譯極易報錯或 offset 錯亂。
    *   **解法**：建立分離架構。
        *   `avstream_dispatch.c` (純 C 檔)：包含所有的 KS Descriptor (Filter, Pin, Node)、Dispatch table 和 callback 函數。
        *   `hw_hal.cpp` (C++ 檔)：處理 RP1 暫存器、MMIO 讀寫、I2C 邏輯。
        *   透過 `extern "C"` 的標頭檔 (`hal_api.h`) 讓 `.c` 去呼叫 `.cpp` 實作的硬體操作。

### 3. DeviceMFT 軟體 ISP

**[Fact] DeviceMFT 是一個 User-mode 的 COM 元件 (Media Foundation Transform)，掛載在相機圖形的最底層。**

*   **註冊與掛載**：
    *   在 AVStream 驅動的 `.inf` 檔中，透過 `AddReg` 將你的 MFT CLSID 寫入 Registry 的 `CameraDeviceMftCLSID` 鍵值。
    *   當 Camera App 打開時，Pipeline 會自動將你的 DeviceMFT 插入在 AVStream Pin 的正上方。
*   **Input / Output 轉換**：
    *   **Input**：接收來自 AVStream 的 `MEDIASUBTYPE_RP1_RAW10`。
    *   **Output**：向 OS 宣告支援 `MFVideoFormat_NV12`。
    *   **ProcessInput**：將 RAW10 Buffer 暫存。
    *   **ProcessOutput**：在這裡執行 **Debayer**。
    *   **最無腦演算法**：
        1.  Unpack RAW10 (5 bytes -> 4 個 16-bit 變數)。
        2.  Bilinear Debayer (Bayer BGGR -> RGB)。
        3.  簡易 Color Matrix (RGB -> YUV) + 白平衡增益乘法。
        4.  將 Y/U/V 寫入 NV12 的 Y-plane 與 UV-plane。
        *(註：這部分未來可掛 NEON intrinsic 優化)*。
*   **3A 控制迴圈 (Control Loop)**：
    *   **AE/AWB 計算**：在 `ProcessOutput` 掃描像素時，順便累加整張圖的 Y (亮度) 算平均值；累加 R/G/B 的總和算比例 (AWB)。(參考 libcamera 裡最簡單的 Mean Luminance 演算法)。
    *   **打回 Kernel**：
        1.  DeviceMFT 計算出新的 Exposure Time 和 Gain。
        2.  MFT 呼叫 `IKsControl::KsProperty`，發送自訂的 KSPROPERTY (例如 `KSPROPERTY_RP1_CAM_EXPOSURE`) 到 Kernel。
        3.  AVStream Miniport 收到 Property Request，透過 I2C 寫入 IMX708 的 `0x0202` (Integration Time) 和 `0x0204` (Analog Gain)。
        4.  下下張 Frame 就會生效。

### 4. PCIe DMA / IOMMU 在 WoA 的現實 (成敗關鍵)

**[Fact] ARM64 Windows 對 DMA 實施嚴格的 IOMMU (SMMU) 隔離。這絕對是相機有無畫面的生死線。**

*   **錯誤做法**：在 Kernel 用 `MmAllocateContiguousMemory`，然後用 `MmGetPhysicalAddress` 把實體位址塞給 RP1 CFE。**這在 WoA 會直接觸發 SMMU Fault 甚至 Bugcheck (DRIVER_VERIFIER_DMA_VIOLATION)**。
*   **正確做法 (WDF DMA 框架)**：
    1.  建立 DMA Enabler：
        ```c
        WDF_DMA_ENABLER_CONFIG dmaConfig;
        WDF_DMA_ENABLER_CONFIG_INIT(&dmaConfig, WdfDmaProfilePacket, 4096); // RP1 CFE 不需要 64-bit DMA 可用 Packet
        WdfDmaEnablerCreate(Device, &dmaConfig, WDF_NO_OBJECT_ATTRIBUTES, &DmaEnabler);
        ```
    2.  分配 Common Buffer (例如 10MB，夠放幾張 RAW)：
        ```c
        WdfCommonBufferCreate(DmaEnabler, BufferLength, WDF_NO_OBJECT_ATTRIBUTES, &CommonBuffer);
        ```
    3.  取得位址：
        *   `VirtualAddress = WdfCommonBufferGetAlignedVirtualAddress(CommonBuffer);` (CPU 讀資料用)
        *   `LogicalAddress = WdfCommonBufferGetAlignedLogicalAddress(CommonBuffer);` (**[關鍵] 這是 IOVA，把這個值寫入 CFE 的 DMA_BASE 暫存器**)
*   **IOMMU 的現實**：Windows HAL 會自動設定 SMMU 頁表，將 `LogicalAddress` 映射到實體記憶體。對 RP1 (PCIe 裝置) 而言，它只管對 `LogicalAddress` 發起 PCIe MemWrite 即可。

### 5. 第一個里程碑：最小可行性驗證 (MVP) 順序

為了不陷入「寫了 1 萬行程式碼，打開螢幕全黑，不知道哪裡錯」的地獄，請嚴格按照以下步驟驗收：

*   **Step 1: I2C 通訊與電源 (無關影像)**
    *   **動作**：實作 RP1 GPIO 拉高 XSHUTDN，供電 EXTCLK。實作 I2C 讀寫。
    *   **驗收**：Kernel 啟動時，能透過 I2C 讀取 IMX708 暫存器 `0x0000` (Chip ID)，並成功印出 `0x0708`。
*   **Step 2: 盲測 CFE DMA (無關 Windows AVStream)**
    *   **動作**：分配 WDF Common Buffer，將位址填入 CFE。透過 I2C 下達 IMX708 開始串流 (Stream ON)。
    *   **驗收**：用 WinDbg 監看 Common Buffer 的 Virtual Address。如果記憶體內容從 `0x00` 變成非 0 的雜亂資料，且 CFE 觸發了 Frame End 中斷，**恭喜，最難的硬體牆已經打穿。**
*   **Step 3: AVStream Dummy 流 (無關 DeviceMFT)**
    *   **動作**：寫死一個 AVStream 驅動，宣稱輸出標準 NV12（假的）。DPC 收到中斷後，不管 RAW，直接在 KSSTREAM_POINTER 填滿綠色 (Y=150, U=43, V=21)。
    *   **驗收**：打開 Windows 內建「相機」App，畫面出現穩定的全綠畫面，不當機，FPS 正常跳動。這證明 AVStream 骨架與 Frame Rate 控制完美運作。
*   **Step 4: MFT RAW 穿透與粗糙 Debayer**
    *   **動作**：AVStream 改輸出自訂 RAW GUID。掛載 DeviceMFT。MFT 裡寫一個最爛的取樣（例如只拿 RAW10 的其中 8 bits 當作黑白 YUV 的 Y，UV 寫死 128）。
    *   **驗收**：打開相機 App，看到「有輪廓、會動的黑白/網格畫面」。這證明 Pipeline (Kernel -> User MFT -> App) 零拷貝資料流完全打通。
*   **Step 5: 影像品質與 3A 補全**
    *   **動作**：在 MFT 實作真正的 Bilinear Debayer、Color Matrix，並透過 KSPROPERTY 把 AE/AWB 打回 Kernel。
    *   **驗收**：畫面顏色正常，用手電筒照鏡頭畫面會自動變暗 (AE 運作)。
