這是一份針對將 Infineon WHD (Wi-Fi Host Driver) 移植到 Windows on ARM64 (Raspberry Pi 5 CYW43455) 並結合 NetAdapterCx 與 Windows SDIO (`sdbus.sys`) 的極度深水區技術指南。

### 1. WHD Porting Layer 確切要實作的函式清單

在 WHD 架構中，你需要提供三個主要的抽象層：**RTOS (OSAL)**, **SDIO Bus (HAL)**, 以及 **Resource & Buffer (Host Integration)**。

#### (a) RTOS 抽象層 (`cyabs_rtos` / OSAL)
WHD 需要你提供執行緒、同步機制與時間管理。在 Windows 核心中，這些全部必須跑在 `PASSIVE_LEVEL` (IRQL 0)。
*   **Zephyr 對照:** `modules/hal/infineon/abstraction-rtos/source/COMPONENT_ZEPHYR/cyabs_rtos_zephyr.c`

**必須實作的原型 (以 `cy_rtos_` 命名空間為例)：**

```c
// 1. Thread (對應 Windows: PsCreateSystemThread / PsTerminateSystemThread)

                                cy_thread_priority_t priority, cy_thread_arg_t arg);
cy_rslt_t cy_rtos_exit_thread(void);
```

WHD 需要三支檔案：`cyfmac43455-sdmac.bin` (FW), `cyfmac43455-sdmac.clm_blob` (Regulatory), `cyfmac43455-sdmac.txt` (NVRAM)。
*   **Zephyr 對照:** `modules/hal/infineon/wifi-host-driver/src/whd_resources.c` 或 Board 專屬實作。

在 Windows 中，你可以把這三個檔案編譯進 `.sys` 作為資源 (Resource)，或者在 DriverEntry 時透過 `ZwReadFile` 讀進 PagedPool 記憶體中。你需要提供以下 Function Pointers 給 WHD：

### 2. WHD Top-Level 使用流程 (Initialization to AP Join)

此流程發生在你的 Driver 初始化階段 (例如在 NetAdapterCx 的 `EvtAdapterPrepareHardware` 或某個專屬的 `PASSIVE_LEVEL` Worker Thread 中)。

**Step 1: 準備核心結構與 Callback (Pseudocode)**
```c
whd_init_config_t init_config = { .thread_stack_size = 8192, .thread_priority = 10, .country = WHD_COUNTRY_WORLD_WIDE };
whd_resource_source_t res_ops = { .whd_resource_size = my_res_size, .whd_get_resource_block = my_res_block };
whd_buffer_funcs_t buffer_ops = { /* 提供封包記憶體分配 callback，見下段 */ };
whd_netif_funcs_t netif_ops   = { .whd_network_process_ethernet_data = my_rx_handoff };
whd_driver_t whd_drv;
```

**Step 2: 初始化 HAL SDIO Bus**
```c
cyhal_sdio_init(&my_sdio_obj, ...); // 這裡面要準備好跟 sdbus.sys 通訊的 WDFIOTARGET
```

**Step 3: 初始化 WHD 核心**
```c
// 建立 WHD 內部 Thread / Queue
whd_init(&whd_drv, &init_config, &res_ops, &buffer_ops, &netif_ops);
```

**Step 4: 將 WHD 與 SDIO Bus 綁定**
```c
// 告訴 WHD 怎麼透過 CMD52/53 講話
whd_bus_sdio_attach(whd_drv, &my_sdio_obj); 
```

**Step 5: 啟動 Wi-Fi (觸發 Firmware Download)**
```c
whd_interface_t whd_iface;
// 這裡會耗時數秒。WHD 會透過 sdio bulk transfer 把 .bin 和 .nvram 寫進晶片，並啟動晶片內核
whd_wifi_on(whd_drv, &whd_iface); 
```

**Step 6: Network Interface 設定**
*此時實體層已準備好，WHD 會返回一個 `whd_interface_t` 的 Handle。如果是第一張網卡通常就是 Primary Interface。*
```c
whd_mac_t mac_addr;
whd_wifi_get_mac_address(whd_iface, &mac_addr);
// (此時你應該把這個 MAC Address 回報給 NetAdapterCx)
```

**Step 7: 加入 AP (Join)**
```c
whd_ssid_t ssid = { .length = 6, .value = "MyWiFi" };
uint8_t password[] = "12345678";
// 阻塞呼叫，直到完成 4-way handshake
whd_rslt_t res = whd_wifi_join(whd_iface, &ssid, WHD_SECURITY_WPA2_AES_PSK, password, sizeof(password));
if (res == WHD_SUCCESS) {
    // 通知 NetAdapterCx Link Up (NetAdapterSetLinkState)
}
```

### 3. 封包交接 (Packet Handoff: Rx / Tx)

這是與 NetAdapterCx 結合最關鍵的地方。WHD 不懂 NDIS 或 `NET_PACKET`，它只懂自己的 `whd_buffer_t`。你必須實作 `whd_buffer_funcs_t` 來做轉換。

為了簡化，實務上在 WoA 移植 V1，**建議使用中介的 Lookaside List** 來給 WHD 用，在 Rx/Tx 邊界做一次 Memory Copy (拷貝到 NetAdapterCx 的 Ring Buffer)。

#### (a) 緩衝區管理 Callback (`whd_buffer_funcs_t`)
WHD 收發封包都會跟你要 Buffer。
```c
// 需查 WHD source 確認函式指標確切定義，一般如下：
typedef struct {
    // WHD 要一塊乾淨的記憶體裝封包
    whd_result_t (*whd_host_buffer_get)(whd_buffer_t *buffer, whd_buffer_dir_t direction, unsigned short size, uint32_t timeout_ms);
    // WHD 用完封包了，請你釋放
    void (*whd_buffer_free)(whd_buffer_t buffer);
    // WHD 要在封包頭部增加/移除 SDPCM 標頭
    uint8_t* (*whd_buffer_get_current_piece_data_pointer)(whd_buffer_t buffer);
    uint16_t (*whd_buffer_get_current_piece_size)(whd_buffer_t buffer);
    whd_result_t (*whd_buffer_add_remove_at_front)(whd_buffer_t *buffer, int32_t add_remove_amount);
} whd_buffer_funcs_t;

// [實作技巧]：你的 whd_buffer_t 可以強制轉型為自定義結構指標：
typedef struct {
    LIST_ENTRY ListEntry;
    uint8_t* payload_start;
    uint8_t* current_ptr; // add_remove_at_front 會移動這個指標
    uint32_t length;
    uint8_t data[2048]; // 實際資料區塊
} MY_WHD_BUFFER, *PMY_WHD_BUFFER;
```

#### (b) Rx 方向 (WHD 收到封包 -> Windows)
1. 晶片觸發 SDIO 中斷。
2. Windows `sdbus.sys` 呼叫你註冊的 Interrupt Callback。
3. 你在 Callback 中 Set Event 通知 WHD Thread。
4. WHD 內部 Thread 醒來，發送 CMD53 讀取資料，剝除 SDPCM 標頭。
5. WHD 呼叫你註冊在 `whd_netif_funcs_t` 的 Rx Callback：
```c
// WHD 內部呼叫此函式將 802.3 Ethernet 封包交給你
void my_rx_handoff(whd_interface_t ifp, whd_buffer_t buffer) 
{
    PMY_WHD_BUFFER my_buf = (PMY_WHD_BUFFER)buffer;
    
    // 1. 取得 NetAdapterCx 的 Rx Ring
    // 2. 獲取下一個可用的 NET_PACKET / NET_FRAGMENT
    // 3. memcpy(net_fragment_virtual_address, my_buf->current_ptr, my_buf->length);
    // 4. 通知 NetAdapterCx 推進 Rx Queue
    
    // 5. 重要：WHD 把所有權交給你了，你必須負責 Free 掉這個 WHD buffer！
    my_buffer_funcs.whd_buffer_free(buffer); 
}
```

#### (c) Tx 方向 (Windows 送出封包 -> WHD)
1. Windows 網路層要送封包，觸發 NetAdapterCx 的 `EvtTxQueueAdvance`。
2. 你的 Driver 走訪 `NET_RING` 取得 `NET_PACKET`。
3. 你的 Driver 呼叫 `whd_host_buffer_get` 產生一個 WHD Buffer。
4. 將 `NET_FRAGMENT` 的資料 `memcpy` 到 WHD Buffer 中。
5. 呼叫 WHD API 送出：
```c
// Tx 方向你呼叫這個函式！(需查 WHD source: 有些版本叫 whd_network_send_ethernet_data)
void EvtTxQueueAdvance(NETPACKETQUEUE TxQueue)
{
    // ... 迴圈取得 NET_PACKET ...
    whd_buffer_t tx_buf;
    my_buffer_funcs.whd_host_buffer_get(&tx_buf, WHD_NETWORK_TX, packet_len, 100);
    
    // 複製資料進 tx_buf...
    
    // 呼叫 WHD 送出 (PASSIVE_LEVEL)
    // 內部語意：WHD 會在此 buffer 前面插入 SDPCM Header，然後排入內部 TX Queue，
    // 最後透過 SDIO CMD53 寫入晶片。寫完後 WHD 會「自動呼叫」whd_buffer_free。
    whd_network_send_ethernet_data(whd_iface, tx_buf);
    
    // 標記 NetAdapterCx 的 packet 為已完成
}
```

### 總結
在 WoA 移植上，**千萬不要嘗試直接把 `NET_PACKET` 轉型成 `whd_buffer_t`**，因為 WHD 在 `whd_buffer_add_remove_at_front` 操作時會頻繁修改資料指標以處理 Header (SDPCM, BDC 等封裝)，而 NetAdapterCx 的記憶體佈局非常嚴格。先用一個獨立的 Pool 實作 `whd_buffer_t` 配合記憶體拷貝，等連上 AP 並能 ping 通後，再考慮 Zero-Copy 最佳化。
